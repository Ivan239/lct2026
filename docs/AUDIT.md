# Аудит сгенерированных слайдов

Аудит — часть пайплайна, а не внешняя проверка: он выполняется на каждой
генерации по готовому `.pptx`, его находки возвращаются вместе с колодой и
показываются в интерфейсе рядом с превью.

Проверки делятся на два класса, как того требует ТЗ:

- **Детерминированные** — читают сам файл (координаты, размеры, кегли, цвета,
  ссылки на макеты) и пиксели рендера. На одном и том же слайде всегда дают один
  и тот же ответ. Модель не вызывается, токены не тратятся.
- **Контекстуальные** — касаются смысла (заголовок — вывод или просто тема?
  относится ли картинка к теме?) и требуют модели; на повторных прогонах ответ
  может отличаться.

Сейчас **весь автоматический аудит детерминированный**. Контекстуальная часть
описана ниже отдельно и честно помечена как невыполняемая автоматически: в
цикле разработки её роль исполнял человек, глядя на рендеры (150+ прогонов,
журнал в `improvement_runs/`).

## Детерминированные проверки

Реализация — `src/evaluation/deterministic.py` и `src/evaluation/contrast.py`,
веса и шкалы — `docs/evaluation_rubric.md`.

### Вёрстка (Приложение 1 → «Вёрстка»)

| Проверка из ТЗ | Как измеряется | Критерий |
|---|---|---|
| элемент вышел за границы слайда | измеряется **текст**, а не рамка: у дизайнеров рамка регулярно выше содержимого | `9.1`, категориально: есть — значит дефект |
| два блока наложились друг на друга | пересечение **полос текста** (не прямоугольников: у дизайнеров рамки пересекаются по замыслу, 51 срабатывание на нетронутом оригинале); порог 0.7 от меньшей площади | `1.1` |
| текст не поместился в свою рамку | оценка высоты текста против рамки — **не считается дефектом сам по себе**: 32 из 79 боксов авторского шаблона такие, 25 помечены `noAutofit` | учитывается как сигнал, не как ошибка |
| текст обрезан краем слайда | то же, что «вышел за границы», плюс проверка полей | `9.1`, `dop_safe_margins` |
| блоки не выровнены по направляющим | группировка левых краёв, допуск в EMU без округления | `dop_distribution` |
| контент заходит в поля у краёв | поля измеряются у самого шаблона, а не назначаются константой | `dop_safe_margins` |
| картинка растянута | сравнение пропорций с исходным изображением | частично (в разработке) |

### Шаблон

| Проверка из ТЗ | Как измеряется | Критерий |
|---|---|---|
| шрифт не из шаблона / больше двух гарнитур | гарнитуры собираются по деке и сверяются с шаблоном | `dop_noise` |
| кегль не из типографической шкалы | шкала измеряется у шаблона (мода по ролям), а не задаётся константой | `1.1` |
| цвет не из палитры | палитра фонов измеряется по рендерам шаблона | `1.8` |
| слайд собран не на макете из шаблона | все слайды — клоны слайдов шаблона либо синтез на его канве | по построению |
| логотип/колонтитул сдвинуты | chrome-боксы шаблона не трогаются, номера страниц перенумеровываются на месте | по построению |
| контраст ниже 4.5:1 | **по рендеру**, не по XML: схемные цвета идут через карту цветов мастера, и XML систематически врёт. У тонких штрихов цвет чернил берётся как сердцевина на линии «фон → модальный цвет» | `1.1`; там, где фон не измерим (текст поверх картинки), аудит называет причину, а не молчит |

### Плотность

| Проверка из ТЗ | Как измеряется | Критерий |
|---|---|---|
| больше 6 буллетов на слайде | ёмкость слайда ограничена спекой шаблона ещё до генерации | по построению |
| буллет длиннее 15 слов | бюджет длины пункта считается по метрикам шрифта и ширине слота | `3.1` |
| таблица больше 7 строк / 5 колонок | слайды с нативными таблицами не предлагаются под заполнение | не применимо |
| больше 5 серий на диаграмме | диаграммы не генерируются, чужие исключаются | не применимо |
| слайд заполнен меньше четверти / больше трёх четвертей | доля занятой площади; слайды «цифра + подпись» исключены — их разрежённость замысел | `dop_distribution`, `dop_pacing` |

### Целостность

| Проверка из ТЗ | Как измеряется | Критерий |
|---|---|---|
| файл не открывается | структурный аудит пакета + вендоренный ISO-валидатор OOXML; битый пакет не отдаётся никогда | `qa/package_check.py` |
| остался текст-заглушка | словарь заглушек и шаблоны («Заголовок», «Текст», lorem ipsum, «Описание…»), обход **групп и ячеек таблиц** | `dop_no_placeholders`, категориально: любой слайд с заглушкой → 1 |
| пустой слайд или только заголовок | счёт непустых контентных боксов | `dop_orphans` |
| слайд оказался картинкой | выход всегда нативный: текст остаётся текстом | по построению |
| у диаграммы нет подписей осей | диаграммы не генерируются | не применимо |
| два слайда дублируют друг друга | сравнение множеств строк слайдов | `dop_no_dup_slides` |

### Сверх ТЗ — проверки, добавленные по найденным дефектам

| Проверка | Почему появилась |
|---|---|
| `dop_wrap` — слово рвётся посреди | рендер переносит на 2–4% раньше метрик; настоящие разрывы выше 100% бюджета |
| `dop_text_split` — фраза обрывается на предлоге | обрезка по границе клаузы, а не по числу слов |
| `dop_numbers_sourced` — все числа слайда есть в исходных материалах | эталон — числа контент-пакета; ловит выдуманные проценты |
| текст поверх ячеек таблицы | таблица — graphicFrame, её ячейки невидимы обычному обходу |

## Контекстуальные проверки (Валидация контента из Приложения 1)

Эти вопросы требуют модели и сейчас **не выполняются автоматически**:

- заголовок содержит вывод, а не просто называет тему;
- содержимое слайда соответствует заголовку;
- слайд пересказывается одним предложением;
- картинки и иконки относятся к теме слайда;
- нет служебного мусора (реплик спикера, кусков промпта);
- текст без опечаток; вся колода на одном языке.

Частично они закрыты детерминированно: «все цифры есть в исходных материалах» —
`dop_numbers_sourced`; «нет служебного мусора» — проверка заглушек и
переменных-подстановок в тексте модели («в X млн рублей» отклоняется на этапе
генерации с повторным запросом).

Почему контекстуальная часть не включена в продукт: измерение показало, что
мультимодальная модель как судья даёт неадекватные оценки — деку с
дублирующимися слайдами и пустыми нижними половинами она оценила выше 90 из 100,
тогда как человек на тех же рендерах поставил 3–4 из 10. Вместо выдачи
недостоверной цифры аудит честно оставляет этот класс проверок человеку. Слой
подготовлен: включение контекстуальных проверок — это добавление VLM-вызова в
`evaluation/`, интерфейс находок менять не нужно.

## Как аудит виден пользователю

- Находки возвращаются в ответе `/api/generate` полем `warnings` и показываются
  в интерфейсе под галереей слайдов.
- Каждая находка называет слайд и причину; там, где проверка невозможна, она
  сообщает **почему** (например: «контраст не проверен на слайдах 2, 4 — текст
  лежит на картинке, фона для замера нет»).
- Полный отчёт по рубрике (около 30 критериев, взвешенный итог) собирается
  скриптом `scripts/improve_loop.py` и сохраняется в `output/evaluations/`.

## Тесты аудита

Каждое правило закреплено тестом, который падает на коде до этого правила:
`tests/` — 410 тестов, из них про аудит — проверки геометрии, контраста,
заглушек в группах и ячейках таблиц, разрывов слов, чисел из источников.
