Версионируемый промпт одной итерации. Крона присылает короткую ссылку на этот
файл; правила меняются здесь, коммитом, а не в расписании.

Ты судья, а не модель-генератор. Одна итерация = одна дека + одно изменение.
Рабочая папка /Users/ivan239/llm_pres. Перед первым действием прочитай CLAUDE.md,
`docs/TZ_VK.md` (ТЗ кейса) и `docs/TZ_BACKLOG.md` (что из ТЗ ещё не закрыто).

## 1. Генерация

`cd /Users/ivan239/llm_pres && set -a; . ./.env; set +a && .venv/bin/python3 scripts/improve_loop.py --model auto --out-json /tmp/loop_last.json`

- Ротация шаблонов встроена в скрипт: VK Tech → VK Education → регресс (старый
  корпус по кругу) → Tech → Education → **слепой VK WorkSpace**.
- **Слепой шаблон** стоит вместо незнакомого шаблона финальной защиты. Его деку
  генерируй и оценивай, но правки по дефектам, найденным ТОЛЬКО на нём, делать
  нельзя: записывай их в отчёт. Если правка подняла Tech/Education и уронила
  WorkSpace — это переобучение, следующая итерация откатывает её.
- Первый разбор шаблона долгий (54–55 слайдов у Tech/Education): запускай в фоне
  и жди через until-loop, а не чередой sleep.
- Скрипт печатает «Время сборки деки». Больше 5 минут — дефект по ТЗ.
- Модель недоступна / ошибка / битый JSON → `--model GigaChat-2-Max`, при повторе
  ещё раз. Сеть недоступна → запиши «пропущено по сети», ничего не ломай,
  заверши итерацию.

## 2. Ревью: открыть Read каждый PNG

Оцени как жёсткий ревьюер, которому принесли деку на согласование, а не как
автор системы. Пройди чек-лист Приложения 1 ТЗ и по каждой группе назови вслух,
что нашёл:

- **Вёрстка:** выход за край слайда; наложение блоков; текст не влез в рамку или
  срезан краем; блоки не по направляющим макета; заход в поля; растянутые картинки.
- **Шаблон:** шрифт не из шаблона или больше двух гарнитур; кегль вне шкалы
  шаблона; цвет вне палитры; слайд не на макете шаблона; логотип или колонтитул
  сдвинуты; контраст ниже 4.5:1.
- **Плотность:** больше 6 буллетов; буллет длиннее 15 слов; таблица больше 7 строк
  или 5 колонок; больше 5 серий на диаграмме; слайд заполнен меньше чем на ¼ или
  больше чем на ¾.
- **Целостность:** заглушки шаблона (Lorem ipsum, «Заголовок», «Пункт», XXX,
  «вставьте текст» — в шаблонах VK их много); пустой слайд или слайд с одним
  заголовком; слайд-картинка вместо объектов; у диаграммы нет осей, единиц или
  легенды; два слайда дублируют друг друга.
- **Контент (да/нет по картинке):** заголовок — вывод, а не тема; содержимое
  соответствует заголовку; все цифры есть в брифе/контент-пакете; нет служебного
  мусора; вся дека на одном языке; соседние слайды связаны.
- **Известные дефекты проекта:** в деку попал служебный слайд-гайд шаблона
  (VK Education «Шрифт для заголовков», «Интерфейсные иконки»; VK Tech
  «Редактируемый слайд-разделитель»); провал под заголовком; слоты канвы
  заполнены частично; контраст на клонированной канве.
- **Итог:** можно показать клиенту или это скелет с генерик-текстом.

Числа харнесса не заменяют этот взгляд: при расхождении прав рендер.

## 4. Одно изменение

Тип итерации по номеру N будущего отчёта:
- **N нечётное — дефект.** Топ-1 реальный дефект из увиденного, подтверждённый
  на .pptx. Чинить общим правилом: код вида `if template_id == ...` или правила
  под конкретный текст шаблона запрещены — на защите шаблон будет незнакомый.
- **N чётное — шаг по ТЗ.** Следующий невыполненный шаг из `docs/TZ_BACKLOG.md`
  (пункты `[⏸]` пропускать). Большой пункт сначала раздели на шаги в бэклоге.

В любой итерации:
- Правки ядра (two_phase, generator, matcher, deck_style, synthesizer, slide_kit,
  qa) проверяй рендером и глазами: «до» и «после» на одной и той же деке.
- Новые промпты — сразу отдельным файлом, не строкой в коде (требование ТЗ).
- Модели в продукте — только открытые веса ≤35B (Apache 2.0 / MIT). Claude —
  только ревьюер этого цикла и в продукт не входит.
- Пункт 11 плана (ёмкость 3 колонки против 4 мыслей) не трогать.
