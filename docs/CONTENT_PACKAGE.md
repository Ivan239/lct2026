# Контент-пакет: формат

ТЗ требует «импорт и декомпозицию шаблонов презентаций и контент-пакетов», а
генерацию — «в контексте выбранного шаблона и контент-пакета». Организаторы
пакет не выдают (подтверждено 19.09.2026), поэтому формат наш. Код —
`src/content_package/loader.py`, тесты — `tests/test_content_package.py`.

## Структура

Папка или `.zip` с такой папкой:

```
package/
  package.json   необязательный: метаданные
  brief.md       ОБЯЗАТЕЛЬНЫЙ: текст автора — о чём дека и зачем
  facts.md       необязательный: факты, по одному на строку
  data/*.csv     необязательные: таблицы данных
  images/*       необязательные: .png .jpg .jpeg .webp
```

### package.json

```json
{
  "title": "Платформа «Поток»",
  "purpose": "product",
  "slides": 12,
  "audience": "коммерческие директора",
  "tone": "деловой, с опорой на цифры",
  "language": "ru",
  "images": {"dashboard.png": "Экран единого дашборда"}
}
```

- `purpose` — назначение из ТЗ: `feature` (фича), `product` (продукт),
  `project` (проект), `initiative` (инициатива).
- `slides` — желаемый объём; ТЗ по умолчанию просит 10–15.
- `images` — подписи к картинкам; без подписи берётся имя файла.
- Нет `title` — берётся первая строка `brief.md`.

### facts.md

Строки `- …`, `* …`, `1. …` или просто строки; `#` — комментарий. Это эталон
для проверки аудита «все цифры и факты со слайда есть в исходных материалах»:
цифры из `brief.md`, `facts.md` и таблиц собираются в множество `numbers`.

### data/*.csv

Первая строка — заголовки. Разделитель — запятая, точка с запятой или
табуляция (определяется сам), кодировка UTF-8, BOM допустим. Колонки, где все
значения числа, помечаются как `numeric_columns` — это кандидаты в серии
диаграммы.

## Почему части держатся раздельно

Разным шагам нужны разные части: диаграмме — таблица как таблица, аудиту —
цифры как множество, вёрстке — список картинок. Склеить всё в один текст
значит потерять это. Пока нижние шаги учатся брать части, `to_brief_text`
собирает пакет обратно в один бриф, и текущий пайплайн работает на пакете уже
сейчас.

## Ошибки

Пакет, которым нельзя пользоваться, отклоняется с `ContentPackageError` и
причиной: нет `brief.md`, пустой бриф, неизвестный `purpose`, `slides` вне
3–30, битый `package.json`, небезопасный путь в архиве.

## Как подать пакет в сервис

`POST /api/generate/package` — multipart-форма: `template_id`, `file` (.zip
пакета), необязательный `model`. Пакет раскладывается на части, бриф с фактами
и таблицами уходит в планировщик (`to_brief_text`), а цифры пакета становятся
эталоном проверки «все цифры со слайдов есть в исходных материалах»: каждая
цифра деки, которой в пакете нет, приходит в `warnings` ответа
(`kind: numbers_not_in_source`, по слайду). Битый пакет — ответ 422 с
причиной. Архив распаковывается в рабочую папку запроса и удаляется вместе с
ней.

Обычный `POST /api/generate` с брифом-строкой делает ту же проверку, эталон —
цифры самого брифа.

Проверка сравнивает по значению и не считает: производные цифры («67%» как
(94 − 31) / 94) и округления («~860» из 864) она покажет как «нет в исходных
материалах». По ТЗ это верно, и пользователь видит, какую цифру проверить.
