# Итерация №93 — измеритель переполнений завышал в пятнадцать раз

## Генерация: пропущена по сети (семьдесят восьмой раз подряд), за секунды

Деки от живой модели нет, оценка 10.1 не выставлялась.

## Что увидел глазами

Взял пункт 1 очереди — «найти среди оставшихся переполнений видимый дефект».
Разложил число пробника на конкретные боксы, и оно рассыпалось:

```
universal 15 боксов: 13 — одностр��чные, промах 0.01in
  слайд 3  H=0.12 → 0.13  8pt  '2025'         ← собственный текст дизайнера
  слайд 3  H=0.12 → 0.13  8pt  '03'           ← номер страницы
  слайд 3  H=0.36 → 0.38  24pt '-40%'         ← KPI-цифра в своём боксе
```

Посмотрел рендеры этих слайдов: ни одного дефекта. Дизайнер верстает бокс по
высоте прописной буквы, а не по полной строке шрифта, — и никакой запас на
перенос эти боксы не спасёт, потому что переносить там нечего.

## Разбор

`boxes_over_at_render_wrap` (iter91) отвечал не на свой вопрос. Название и
докстрока говорят «сколько боксов переполнится ИЗ-ЗА раннего переноса», а
считалось «оценка текста выше рамки» — а это, по правилу критерия 1.1, вообще не
мера дефекта (у дизайнеров 32 из 79 боксов такие).

Вторая причина завышения: все абзацы бокса мерились САМЫМ КРУПНЫМ кеглем
(`max(sizes)`). На KPI-карточке подпись 11pt переносилась по ширине как 24pt.

## Правка

Бокс считается только когда безопасная ширина стоит ему ЛИШНЕЙ СТРОКИ по
сравнению с полной, — ровно то, что предотвратил бы запас в `enforce_text_fits`.
Каждый абзац мерится своим кеглем и своим межстрочным.

```
переполнится при рендерном переносе: universal 15 → 1, study 3 → 1, mono 2 → 1
итоги 99.5 / 99.5 / 100.0 / 99.5 — не изменились (число не входит в оценку)
```

Оставшиеся три — титул обложки study, подзаголовок обложки universal и заголовок
слайда 2 mono. **Посмотрел рендеры глазами**: все три спокойно ложатся в пустоту
под собой, ни обрезки, ни наложения. То есть видимого дефекта от рендерного
переноса на этих деках НЕТ, и глобальный запас в `enforce_text_fits` вводить
по-прежнему не на чем — пункт очереди закрыт замером, а не правкой.

## Чужой тест, упавший от правки

`test_the_wrap_overflow_count_ignores_the_designers_own_boxes` (iter91) держит
верную мысль — текст дизайнера не наш, — но его фикстура была 28pt в 3in боксе,
то есть «выше рамки при любой ширине». Под новой меркой она перестала считаться,
и тест упал по причине, к его мысли отношения не имеющей. Починил ФИКСТУРУ
(вывел ширину из замера текста, как в новом тесте), а не мысль. Соблазн был
ослабить мерку обратно.
