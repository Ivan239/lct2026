# Итерация №98 — проверка, которая не разделяет модель с генератором

## Генерация: пропущена по сети (восемьдесят третий раз подряд), за секунды

Деки от живой модели нет, eval JSON не создан, оценки по рубрике не применялись.

## Моя оценка 10.1 (по офлайн-деке survey-31): **4 из 5**

Без изменений со вчера — деку я сегодня не менял. Взвешенный итог харнесса
**99.5**.

## Что делал

Пункт 2 очереди: харнесс слеп ровно там же, где генератор, потому что считает
строки ТОЙ ЖЕ моделью fontTools. Когда модель ошиблась на жирном (iter96), с ней
согласились все проверки: дека получила 99.5 с пунктом, напечатанным сквозь
вторую строку заголовка.

Пиксели этой модели не разделяют. Но и подписей на них нет, и две первые
формулировки на этом умерли:

```
1. считать чернильные строки ВНУТРИ бокса        → не нашла ничего:
   непредсказанная строка по определению вне бокса
2. смотреть НИЖЕ бокса                            → сработала на всех здоровых
   деках: там текст следующего бокса, и пиксель не скажет, чья это строка
3. упирается ли текст в НИЖНИЙ КРАЙ своего бокса  → работает
```

Третья формулировка ничего не приписывает: бокс, посчитанный под свой текст,
оставляет последней строке просвет; бокс, посчитанный под одну строку там, где
рисуется две, дожимает вторую до края. Это ровно то условие, при котором
ошибается всё, что ставится ниже титула.

## Ещё одна ложная тревога, снятая до коммита

Первый рабочий вариант пометил два слайда Учебного. Проверил: это НАТИВНЫЕ
слайды — бокс титула там дизайнерский, а у дизайнера текст выходит за рамку по
замыслу (правило docs/LESSONS.md, третья такая ловушка). Проверка ограничена
СИНТЕЗИРОВАННЫМИ слайдами, где бокс наш.

## Честная граница

Дефект iter96 сегодня не воспроизводится отключением одних лишь жирных метрик:
кап зазора (iter97) изменил компоновку, и титул при тех же метриках выходит
однострочным. Поэтому срабатывание доказано на ПОСТРОЕННОМ случае — рендер
рисуется тестом (PIL), а не LibreOffice: под проверкой пиксельная логика, а не
рендерер. Тишина на четырёх боевых деках проверена прогоном пробника.

Тесты: **285 passed** (+3): срабатывает на срезанном боксе, молчит на боксе по
размеру, не судит нативный слайд.

## Сравнение с прошлой итерацией

iter97 закрыла спор о зазоре правкой генерации; сегодня — про инструмент,
которым такие правки проверяются. Две отброшенные формулировки стоили большей
части итерации, и это правильная цена: измеритель, который молчит всегда или
кричит всегда, хуже отсутствия измерителя — он приучает себе не верить.
