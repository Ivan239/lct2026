# Итерация №6 — защита от «сирот»/вдов в буллетах (GigaChat-2-Pro)

- **Модель:** GigaChat-2-Pro, 7 слайдов, итог прогона **~89** → после фикса (регенерация) **94.4**.
- Bg-фикс и остальное держатся; контраст чист.

## Что увидено глазами

На двухколоночном слайде («До и после Потока») почти каждый переносящийся буллет
оканчивался ОДНИМ словом на второй строке: «…по разным / источникам», «…ручной сбор и /
обработка», «…данные в едином / интерфейсе», «…отчеты и / прогнозы», «…принятия /
решений». ~5 висячих строк на одном слайде — видно как неаккуратность. Детерминированный
`dop_orphans` это ловил (7 из 10), балл 2.

Оставшийся крупный визуальный вопрос — вертикальный дисбаланс синтез-слайдов — снова
отложен: он от НАМЕРЕННОГО `_centered_top`, безопасной узкой правки нет (нужен отдельный
разбор «дизайн vs дефект»).

## Что реализовано и ПРОВЕРЕНО РЕНДЕРОМ + ГЛАЗАМИ

Типографская защита от вдов — склейка последних двух слов буллета неразрывным пробелом
(U+00A0), чтобы перенос не оставлял финальное слово одно:

- `two_phase._guard_widow` (в `_enforce_text_budgets`): для буллетов/колонок с ≥3 словами
  заменяет последний пробел на NBSP. LibreOffice/PowerPoint чтут NBSP как неразрывный.
- Детектор `deterministic._tokens` + `_is_widow`: токенизация теперь неразрывна по NBSP
  (склеенная пара = один токен = ДВА видимых слова, не вдова). Ключевое свойство: в
  существующем контенте NBSP нет, `_tokens` строго == `.split()` → **ноль регрессии**
  (подтверждено: все прежние тесты зелёные). `text_fit` трогать не пришлось — Python
  `.split()` и так расщепляет NBSP, высота не меняется.

Проверка:
- Реальный рендер (регенерация того же слайда): каждый переносящийся буллет теперь
  оканчивается ДВУМЯ словами — «разным источникам», «едином дашборде», «роста
  конверсии». Висячие строки на слайде ушли (смотрел глазами).
- `dop_orphans`: 7/10 → 3/10 (балл 2 → 4).
- Тесты: **102 passed** (unit: `_guard_widow`, `_tokens` no-op без NBSP, `_is_widow`
  не флагает склейку).
