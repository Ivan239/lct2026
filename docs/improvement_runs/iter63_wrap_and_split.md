# Итерация №63 — ещё два критерия питались от той же негодной меры

## Генерация: пропущена по сети (сорок восьмой раз подряд), за секунды

Деки от живой модели нет, оценка 10.1 не выставлялась.

## Что показал системный проход

Прогнал все критерии по восьми НЕТРОНУТЫМ шаблонам и выписал всё, что ниже 5:

```
dop_text_split: 1 из 5 на авторском шаблоне  ← самый жёсткий ложный вердикт в харнессе
dop_wrap:       3 из 5, «32 боксов с некорректным переносом»
```

Оба — те же самые 32 бокса `_overflows`, про которые iter61 замерила: 25 из них
помечены `noAutofit`, дизайнер намеренно держит рамку меньше текста. В iter62 я
починил 1.1 и НЕ проверил, кто ещё читает тот же сигнал. Читали ещё двое.

## Что теперь считают

**dop_wrap** — по своему же названию: слово, которое не влезает в ширину бокса и
будет разорвано посреди («Автоматизаци/я», «е-/жемесячно» из iter57). Проект с
этим дефектом воюет с iter18, а критерий про перенос его не мерил.

**dop_text_split** — только «стены текста». Переполнение рамки о плохом
разбиении не говорит ничего.

## По дороге нашлась ошибка в самой проверке

Первый замер дал одно срабатывание на авторском корпусе — сноска survey-69,
10.5pt. Полез смотреть: шрифт у неё `+mn-lt`, и я решил, что дело в токене темы.
Оказалось нет — резолвер разбирает токен правильно, метрики верные
(«question» = 39.7pt при бюджете 172pt). Настоящая причина:
`cap_size_to_longest_word` стартует с `round(size_pt)`, поэтому для 10.5pt
возвращает 10 — даже когда ничего не ужималось. Сравнение с ОКРУГЛЁННОЙ базой
убрало последнее срабатывание:

```
разрывов слов по 217 авторским слайдам: 0
```

Полезно: первая гипотеза («виноват токен темы») была правдоподобной и неверной,
и отличить их удалось только прямым замером ширины слова.

## Шкала

Ноль на всём авторском корпусе позволил сделать dop_wrap категориальным, как
9.1: разрыв слова виден на слайде независимо от того, сколько вокруг хороших
боксов. Проверка это подтвердила — до ужесточения посаженный дефект iter57
получал **5 из 5** («1 бокс из 11» = 9%), после стал 2.

```
дефект iter57 (подпись 24pt в узком боксе): dop_wrap 5 → 2
восемь авторских шаблонов: dop_wrap 5, dop_text_split 5 (было 3 и 1)
наши деки: 99.4 / 99.4 / 100.0 / 98.8 — без изменений
```

Тесты: **191 passed** (+4). На HEAD падают два содержательно: посаженный дефект
оценивался на 5, а нетронутый survey-31 — «32 боксов с некорректным переносом».

## Сравнение с прошлой итерацией

iter62 починила 1.1 и остановилась на этом. Урок ровно тот, что записан в
CLAUDE.md про фиксы в двух путях: **исправив негодный сигнал, найти всех его
потребителей**. Их было трое, и два оставшихся ставили авторским декам 1 и 3.
