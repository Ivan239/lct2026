# Итерация №32 — узкая канва съедала синтезированный слайд целиком

## Генерация: пропущена по сети (семнадцатый раз подряд)

Прогон поднял **GigaChat-2 × Т—Ж Учебный** и упал на OAuth
(`ngw.devices.sberbank.ru:9443`, connection refused). Деки от модели нет →
**оценку 10.1 и взвешенный итог не выставлял.**

Чтобы всё-таки СМОТРЕТЬ на слайды, собрал деку офлайн так, как её собирает сам
пайплайн: `build_spec` → `plan_from_outline` (слайды выбирает матчер) →
`_synth_canvas_hints` → `generate`. Текст блоков написал сам. Это не заменяет
оценку модели, но даёт честный предмет для глаз.

## Ложный след, который я не стал чинить

Сначала собрал деку рукотворным планом, назначив роли слайдам вручную, и увидел
«потерю контента»: у слайда-сравнения доехал только заголовок. Проверил карту
архетипов — слайд 5 Учебного имеет архетип **title**, двухколоночного семейства
в шаблоне нет вообще, и матчер туда роль никогда не отправит. То есть дефект был
артефактом моего плана. Пересобрал через матчер: сравнение, картинка и финал
честно уходят в СИНТЕЗ. Чинить несуществующий баг не стал.

## Что увидел глазами на честной деке

Слайд image_caption: **огромная пустая карточка и один заголовок**. Ни
рамки-скелета, ни подписи — то есть ровно та фича, ради которой скелеты и
делались, на этом пути не работала.

## Разбор до причины

Свёл к минимальному воспроизведению:

```
synthesize_image_caption без канвы      → TextBox + img_placeholder (2.39in)
synthesize_image_caption с канвой 10    → только TextBox
```

Дальше — числа:

```
без канвы: bounds 1.22–5.26  титул 1.22 (h=0.83) → below=+2.39  above=-0.35 → рисуем
канва 10:  bounds 3.73–4.76  титул 3.73 (h=0.83) → below=-0.62  above=-0.35 → ПРОПУСК
```

`_prepare_blank_slide` берёт контентные границы из СОБСТВЕННОГО текста канвы —
«дизайнер уже решил, где на этом слайде контент». Но канва РЕИСПОЛЬЗУЕТСЯ под
другую роль, и слайд, у которого своего текста одна низкая строка (дивайдер,
финал), отдаёт полоску 1.03in против шаблонных 4.04in. Титул её съедает, обе
полосы уходят в минус, рамка молча не рисуется.

Замер по корпусу: **по три такие канвы в каждом Т—Ж** (20–39% от полной полосы),
и это ровно те слайды, которые предлагаются под синтез.

## Реализация

- Границы канвы принимаются, только если полоса ≥ 40% шаблонной; иначе фолбэк на
  шаблонные (`_resolve_bounds` — тот же путь, что уже был для канв без текста).
- **Вторая правка появилась из рендера.** С фолбэком рамка нарисовалась — и
  пересекла подвальную линейку, обведя «КОММЕНТАРИЙ» и номер страницы:
  шаблонная полоса меряна по всем слайдам и проходит сквозь мебель, которую клон
  сохраняет. `_clip_to_canvas_chrome` подрезает полосу по chrome самой канвы,
  только у краёв, с зазором 0.12in.

## Проверка

```
image_caption на канве 10   TextBox + img_placeholder 2.39in   (было: только TextBox)
bullet_list  на канве 10    TextBox + блок 2.11in
stats_kpi    на канве 10    TextBox + 6 боксов пар
слайд-сравнение (широкая канва)  не изменился — регресса нет
```

**Посмотрел рендеры глазами**: рамка стоит чисто над подвальной линейкой,
номер страницы и «КОММЕНТАРИЙ» не задеты; слайд стал композицией, а не
одиноким заголовком.

Тесты: **143 passed** (+1). Новый падает на HEAD с «the image slide shipped as
a bare heading» и проверяет обе части фикса — что рамка есть и что она не лезет
в подвал.

## Очередь

1. **[генерация] «КОММЕНТАРИЙ» на клонированных канвах** — заглушка без
   владельца отгружается дословно в подвале КАЖДОГО синтезированного слайда
   (видно на всех рендерах этой итерации). На нативном пути её обнуляет
   `_clear_unclaimed_text`, на клон-пути её никто не трогает.
2. **[harness] Card-макеты: считать пиксели ВНУТРИ геометрии текстовых боксов.**
   Эталон для проверки теперь есть — дека `/tmp/gt/study4.pptx` и мои вердикты
   по её слайдам (все читаемы, ложных срабатываний быть не должно).
3. **[генерация] Пустая верхняя половина** у image_caption: между титулом и
   рамкой остаётся большой провал.
4. Пункт 11 плана — по просьбе пользователя не трогаем.
