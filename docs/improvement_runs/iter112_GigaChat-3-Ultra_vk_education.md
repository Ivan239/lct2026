## Что сделано (чётная — шаг по ТЗ, п. 2)

Шаг «цикл генерирует по пакетам вместо брифа». Взят раньше строки «загрузка
пакета во фронтенде», стоящей выше, — сознательно: пока цикл кормится брифом
без единой цифры, `dop_numbers_sourced` на каждой деке стоит на 1 и не меряет
ничего (iter108: 20 из 20 выдуманы), а фронтенд касается только демо.

`scripts/improve_loop.py`:
- **`--content auto`** (по умолчанию) — три пробных пакета
  `samples/content_packages/` по кругу; бриф — `to_brief_text(package)`,
  эталон цифр — `package["numbers"]` в `run_iteration(source_numbers=…)`.
  Скрипт печатает `content=пакет <имя> (<назначение>)`, бандл хранит его.
- `--content canonical` — старый бриф; `--content <папка|zip>` — любой пакет;
  `--brief-file` — свой бриф, его цифры и есть эталон.
- **Ловушка ротации:** в расписании 6 слотов шаблонов, пакетов 3. Счётчики
  «в ногу» пригвоздили бы контент к шаблону — VK Tech (слоты 0 и 3) вечно
  видел бы один пакет. Счётчик пакетов делает лишний шаг на обороте
  расписания; за три цикла каждый слот видит все три пакета. Тест проверен на
  «в ногу»-варианте: падает с `slot 0 (vk_tech) saw only
  ['feature_smart_search']`.

`docs/LOOP_PROMPT.md` и docs/LESSONS.md: цифры деки сверяются с пакетом; глазом —
не исказила ли модель факт (пример iter110: 410 → 864 подано как «+48%»).

Путь «пакет → планировщик → аудит цифр» проверен боем в iter110 (API);
в цикле он тот же (`to_brief_text` + `source_numbers`). Первая дека цикла по
пакету — следующая итерация.
