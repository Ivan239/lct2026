# Итерация №89 — слайд «одна большая цифра» перестал считаться неравномерным

## Генерация: пропущена по сети (семьдесят четвёртый раз подряд), за секунды

Деки от живой модели нет, оценка 10.1 не выставлялась.

## Пункт очереди

Критерии равномерности освобождают обложку, дивайдер и закрытие — они разрежены
ПО ЗАМЫСЛУ. Макет «цифра 92pt + подпись» ровно из этой компании: заголовка у него
нет вовсе. Но роль у него `stats_kpi`, а освобождать всю роль нельзя — у того же
шаблона второй стат-слайд это восьмибоксовая KPI-доска, плотная как любой
контентный слайд.

Поэтому признак — по СЛАЙДУ: не больше двух контентных боксов, и один из них
показатель (критерий из iter80).

```
замер по всем декам и шаблонам: попадают два больших слайда деки с повтором
и слайд 8 самого Универсального — и больше ничего
стат-слайд с заголовком имеет ТРИ бокса и остаётся в расчёте
```

## Результат

```
дека --repeat 3, Универсальный: 91.2 → 92.2
dop_distribution 4 → 5 (CV 0.39 → 0.26), dop_pacing 4 → 5 (CV 0.38 → 0.28)
обычный бриф: 99.5 / 99.5 / 100.0 / 99.5 — без изменений
```

Штраф был следствием правки iter87: она убрала заголовок с этого слайда (его там
не предусмотрено), слайд стал разрежённым — и харнесс отреагировал на законную
разрежённость. Теперь два изменения согласованы.

Тесты: **264 passed** (+4). Первый падает на HEAD с `CV=0.44` → 4 вместо 5.

## Тест снова был беззубым

Первая фикстура давала ровную деку и без исключения — проходила на HEAD. Пришлось
сделать контентные слайды НАМЕРЕННО плотными: смысл проверки в том, что ОДИН
разрежённый слайд рядом с ними перекидывает разброс через порог. Это уже пятый
раз за сессию, когда «тест зелёный на HEAD» означает «фикстура слабее дефекта».
