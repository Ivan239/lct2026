# Итерация №36 — классификатор не видел ни кегля, ни размера слайда

## Генерация: пропущена по сети (двадцать первый раз подряд)

Прогон поднял **GigaChat-2 × survey-69** и упёрся в OAuth. Деки от модели нет →
**оценку 10.1 и взвешенный итог не выставлял.**

## Сначала — исправление собственной ошибки

Пункт 1 очереди был «многоранные номера страниц survey-дек стираются». Проверил
на файле: у этих боксов **ноль ранов**, потому что это настоящий плейсхолдер
`SLIDE_NUMBER` с полем `<a:fld>`. Циклы очистки идут по ранам и на пустом списке
не делают ничего, так что номера НЕ стираются. Отрендерил и **посмотрел
глазами**: слайд, вырезанный из позиции 24, показывает «1» — поле
перенумеровывается само.

Значит утверждение в отчёте и коммите iter33 («survey-деки теряют номера
страниц») было НЕВЕРНЫМ. Фиксирую здесь, пункт из очереди снимаю.

## Что нашёл вместо этого

На том же рендере увидел деку survey-31 целиком и полез в её карту архетипов:
**30 «other» + 1 «closing»** на 31 слайд. Для реального клиентского шаблона это
значит, что нативных слайдов нет почти совсем.

Большинство — слайды «метка раздела + вопрос + график», и «other» для них по
замыслу верно (чужие данные). Но слайд 0 — это **титул**: логотип, крупный
заголовок «Employee Short Survey Results», декоративная иллюстрация. Посмотрел
рендер глазами — ошибки быть не может.

Разобрал, кто его так пометил:

```
код (правило про картинки): has_oversized_picture = False — картинка 4% площади, не при чём
кластеризация:              слайд 0 — ОТДЕЛЬНЫЙ кластер (медоид 0), не при чём
значит:                     так решил классификатор, глядя на описание
```

А описание было такое:

```
Shapes: 2
- PICTURE (13) at (7.55, 1.03) size 1.71x2.33: ""
- TEXT_BOX (17) at (1.1, 1.94) size 8.15x3.2: "Employee Short Survey Results"
```

Ни кегля, ни размера канвы. По такому описанию титул и подпись неразличимы:
8.15in — это 61% от слайда 13.33in и все 100% от слайда 8in, а четыре слова в
большом боксе могут быть чем угодно. При этом **оба факта уже лежат в структуре**
и просто выбрасывались: у этого заголовка `size_pt = 92`.

## Реализация

`_describe_slide` получил строку `Slide: WxH in` и `, font Npt` у фигур, где
файл кегль указывает. Кегль НЕ выдумывается: Google-Slides-экспорты оставляют
большинство ранов без размера, и подставить туда число значило бы протащить в
классификатор ту же слепоту, из-за которой уже пострадал `_pick_title_shape`.

`CLASSIFIER_VERSION` поднят до 3 — правило docs/LESSONS.md: изменил описание, бампни
версию, иначе старые ярлыки переиграются молча.

## Проверка

```
survey-31 сл.0:  Slide: 13.33x7.5 in ... size 8.15x3.2, font 92pt: "Employee Short Survey Results"
survey-31 сл.4:  ... font 40pt / font 19pt / font 18pt   (метка, вопрос, пояснение)
Т—Ж Моно:        кегль указан у 2 фигур из 14 — ровно там, где он есть в файле
Т—Ж Универсальный: у 3 из 16
```

Тесты: **149 passed** (+2). На HEAD падают (сигнатура без второго аргумента).

## Честная граница этой итерации

Дальше по цепочке — ответ модели, а сети нет двадцать первую итерацию подряд.
Поэтому проверено ДЕТЕРМИНИРОВАННО: описание содержит нужные факты и не
выдумывает отсутствующие. **Улучшилась ли сама классификация — не проверено** и
будет первым делом на следующем прогоне с сетью. Слайд удобен для проверки:
«other» не кэшируется, так что он переклассифицируется в любом случае.

## Сравнение с прошлой итерацией

iter35 чинила композицию синтезированного слайда. Эта — вход классификации, то
есть уровень выше: до сих пор все итерации улучшали то, что делается ПОСЛЕ
разбора шаблона, а здесь оказалось, что на реальном клиентском шаблоне почти
весь шаблон объявлен непригодным ещё на разборе.

## Очередь

1. **[классификация] Проверить на сети**, стал ли титул survey-31 «title».
   Если нет — следующий кандидат: описание не передаёт, что картинка
   декоративная (у неё нет ни доли площади, ни признака «фон»).
2. **[классификация] 30 «other» из 31** — даже если титул починится, слайды
   «вопрос + график» останутся непригодными. Возможно, для таких шаблонов
   правильный ответ не «other», а «использовать текстовую часть, картинку
   выбрасывать».
3. **[harness] Кадровая проверка контраста** осталась фолбэком — проверить,
   много ли слайдов без измеримых боксов.
4. Пункт 11 плана — по просьбе пользователя не трогаем.
