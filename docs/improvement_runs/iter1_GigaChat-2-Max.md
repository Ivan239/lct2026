# Итерация улучшения №1 — GigaChat-2-Max

- **Модель:** GigaChat-2-Max (парсинг шаблона + генерация + судейство).
- **Шаблон-источник:** `output/templates/template_a_corporate.pptx` (пресет, чистый).
- **Бриф:** канонический (платформа «Поток», аналитика продаж, деловой тон) — см.
  `scripts/improve_loop.py::CANONICAL_BRIEF`.
- **Дека:** `output/loop/GigaChat-2-Max/decks/deck_1784889007.pptx` (8 слайдов, 0 skipped).
- **Итог по рубрике:** **94.4 / 100** (после фикса N/A-гейта изображений).

## Главная находка (grounded, подтверждена на файле)

**Слайды 5 и 7 — смысловые дубли.** Оба — stat/KPI-слайды с ОДНИМИ И ТЕМИ ЖЕ тремя
метками метрик, отличаются только числами и заголовком:

- Слайд 5 «Ключевые возможности»: +25% Рост конверсии сделок · −30 ч/мес Экономия
  времени менеджеров · 95% Точность прогнозирования спроса.
- Слайд 7 «Результаты внедрения»: +15% Рост конверсии сделок · −30% Экономия
  времени менеджеров · 95% Точность прогнозирования спроса.

Судья независимо отметил это тремя критериями: 3.4 (повторы), 5.3 (логика нарушена
повтором), 6.1 (порядок). Детерминированный `dop_no_dup_slides` пропускал — текст
не побайтово идентичен.

## Что реализовано и проверено в этой итерации

1. **Детект смысловых дублей слайдов** (`evaluation/deterministic.py::_near_duplicate_slides`):
   слайды, делящие ≥3 идентичных контентных строк (или Jaccard ≥ 0.6 по строкам),
   считаются дублем, даже если числа разные. Проверено: боевая дека
   deck_1784889007 теперь ловит «1 смысловой дубль» (5→4), контрольная различная
   дека ложно НЕ срабатывает (остаётся 5). Тесты: `tests/test_evaluation.py`.
2. **Фикс N/A-гейта изображений** (harness-баг, не дефект деки): GigaChat примерно в
   половине случаев ставит критериям раздела 4 балл «1 — изображений нет» вместо
   N/A. Теперь наличие изображений/диаграмм определяется детерминированно
   (`deck_media`), и неприменимые критерии принудительно N/A, судью о них не
   спрашиваем. Итог перестал занижаться на текстовых деках (88.5 → 94.4).
3. **Фикс судьи: пропуск ключей** — на 22 визуальных критериях за раз GigaChat молча
   терял часть ключей; теперь критерии судятся чанками по 7 с валидацией полноты и
   ретраем (`_require_ids`), плюс устойчивая загрузка картинок к транзиентным 403.

## Что увидено ГЛАЗАМИ (рендеры просмотрены целиком) — то, что числа и GigaChat прозевали

Автооценка дала 94.4, но при взгляде на картинки видны 3 дефекта, которые НИ
детерминированные проверки, НИ судья GigaChat не поймали (все поставили 4.5–5.0):

1. **[КРИТИЧНО] Слайды 6 и 7 почти нечитаемы.** Отрендерились на БЕЛОМ фоне (остальные
   — тёмно-синие), а цвет тела текста остался светло-серым → серый по белому, буллеты
   еле видно. Тот же серый на синем (слайд 3) читается. Значит цвет текста жёстко
   светлый и не адаптируется под фон breather-слайда. Это провал контраста (1.1) +
   рассинхрон фонов (9.3) + реальный баг генерации. Детерминированный чек контраст из
   XML не видит (цвета наследованные), GigaChat поставил читаемости 4.5.
2. **Вертикальный баланс сломан по всей деке.** Слайды 3/4/5/7: контент прижат к
   верхней трети, нижняя половина пустая. GigaChat: «баланс 5/5».
3. **Слайд 5: KPI не на общей базовой линии.** «-30 часов/мес.» переносится на 2
   строки и сидит выше «+25%»/«95%» — ряд цифр скачет.

**Вывод по методологии:** первичной визуальной оценкой в цикле должен быть взгляд
ревьюер на рендеры (каждый 3-часовой запуск), а числа/GigaChat — объективный
бэкстоп и headless-фолбэк. Раннер теперь печатает пути рендеров под баннером «ПОСМОТРИ
ГЛАЗАМИ», шаг судейства в cron переписан на vision-first.

## Очередь (следующие итерации)

0. **[КРИТИЧНО, генерация] Контраст текста на breather-слайдах.** Цвет тела/лейблов
   не переключается под белый фон → нечитаемо (слайды 6/7 выше). Чинить в цвето-логике
   генератора (`deck_style`/синтез фона): выбирать цвет текста по контрасту к фактическому
   фону слайда. Плюс кандидат в объективный бэкстоп — **детерминированная проверка
   контраста по РЕНДЕРУ** (сэмплить текст vs фон из PNG, как `style_profile.slide_background`),
   тогда этот класс ловится без токенов.
0b. **[средний] Вертикальное центрирование контента** в остатке под заголовком, чтобы
   не было пустой нижней половины (перекликается с `synthesizer._centered_top`).

1. **[высокий приоритет, генерация] Убрать смысловую редундантность stat-слайдов.**
   Корень — независимые `generate_block(stats_kpi, …)` тянут из одного пула метрик
   брифа, не зная о уже использованных. Варианты: (а) передавать в генерацию блока
   список уже занятых меток метрик и требовать НОВЫЕ; (б) пост-проверка: если два
   stat-блока делят ≥2 метки — один дифференцировать/схлопнуть. Высокий blast-radius
   (ядро `two_phase`/`generator`), обязательна проверка на реальных файлах рендером
   (правило docs/LESSONS.md), поэтому вынесено в отдельную итерацию, а не сделано наспех.
2. **[средний, темп] Разброс объёма по слайдам** CV≈0.5 (`dop_distribution`/`dop_pacing`
   = 4). Выровнять ёмкости в аутлайне, чтобы слайды не скакали по плотности.
3. **[низкий, текст] Длинные предложения / стиль местами маркетинговый** (3.3, 8.2 = 4).
   Донастройка стайл-преамбулы под «деловой без хайпа».
