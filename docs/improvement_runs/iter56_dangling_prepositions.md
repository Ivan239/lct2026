# Итерация №56 — обрезанный пункт больше не кончается предлогом

## Генерация: пропущена по сети (сорок первый раз подряд), за секунды

## Что проверял

Пункт очереди: доходит ли бюджет символов из iter28 до модели. Прогнал всю
цепочку офлайн с подставным клиентом:

```
промпт слайда-списка Учебного: «bullets: [РОВНО 5 строк, каждая — короткая фраза до 28 символов]»
```

Доходит. Значит 9pt-микротекст, который я чинил в iter51, был во многом
следствием МОЕГО пробника: он подавал 49-символьные пункты в слот с бюджетом 28,
минуя боевую обрезку. (Сама правка iter51 остаётся верной — QA-проход не должен
отменять пол читаемости, — но видимый случай был артефактом пробы.)

## Настоящий дефект, который вскрылся по дороге

Посмотрел, ЧТО боевая обрезка делает с этими пунктами при бюджете 28:

```
'Ручной сбор показателей из'
'Разные форматы выгрузок у'
'Согласование занимало до'
```

Обрезка режет по границе слова — и оставляет висящий предлог. Каждая фраза
читается как оборванная на полумысли, и в таком виде уезжает пользователю.

Починил: после обрезки хвостовые предлоги и союзы отбрасываются.

```
'Ручной сбор показателей'   'Разные форматы выгрузок'   'Согласование занимало'
```

## Заодно — вторая нереалистичность пробника

`offline_probe.py` не применял бюджет символов вовсе. Это тот же класс изъяна,
что и с `count` в iter53: пробник мерил не то, что делает пайплайн. Теперь
применяет.

```
study: 95.6 → 100.0, микротекста нет, пункты набраны шаблонным кеглем
universal 98.4, mono 99.4, survey-31 98.8
```

**Посмотрел рендер глазами**: пункты Учебного в 14pt, как у шаблона, фразы
законченные.

Тесты: **170 passed** (+2). Первый падает на HEAD с
`'Ручной сбор показателей из' == 'Ручной сбор показателей'`. Второй — сквозной
по цепочке бюджета (build_spec → generate_deck → generate_block): iter28 покрыла
только последний переход, так что поломка любого из первых двух была бы не видна.

## Сравнение с прошлой итерацией

iter55 меняла подачу KPI, эта — качество самого текста. И снова полезным
оказалось не «починить дефект», а сначала проверить, настоящий ли он: половина
микротекста была моим пробником, зато рядом нашлось то, что действительно
портит слайд.

## Очередь

1. **[классификация] Проверить на сети** переразбор отравленных кэшей и титул
   survey-31.
2. **[генерация] «Согласование занимало»** — обрезка даёт грамматически целую,
   но смысловую половину. Настоящее решение — просить модель короче (бюджет уже
   в промпте) и не полагаться на обрезку; проверить на живой модели.
3. Пункт 11 плана — по просьбе пользователя не трогаем.
