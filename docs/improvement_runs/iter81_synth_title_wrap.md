# Итерация №81 — заголовок перечёркивался рамкой-скелетом

## Генерация: пропущена по сети (шестьдесят шестой раз подряд), за секунды

Деки от живой модели нет, оценка 10.1 не выставлялась.

## Что увидел глазами

Слайд с картинкой у Универсального на пресете `wordy`: третья строка заголовка
(«подразделения») перечёркнута верхней границей пунктирной рамки.

## Разбор

```
титул 32pt в боксе 9.34in
оценка высоты по полной ширине:      1.02in  → ДВЕ строки
с запасом SINGLE_LINE_SAFETY:        1.53in  → ТРИ строки (так и рисует рендер)
рамка ставилась на 2.98 при тексте до 2.86 — зазор 0.12in
```

Это тот же дефект, что iter64 нашла на обложке: рендер переносит на 2–4%
раньше, чем предсказывают метрики. Тогда я починил `synthesize_title`, а
`_add_title` — заголовок ВСЕХ остальных синтезированных ролей — остался мерить
по полной ширине. Опять расхождение двух путей, про которое docs/LESSONS.md
предупреждает отдельным правилом.

## Правка

`_add_title` меряет высоту и подбирает кегль по бюджету с тем же запасом.

```
рамка 2.98 → 3.46, зазор 0.12 → 0.60in
обычный бриф: 99.4 / 99.4 / 100.0 / 98.8 — без изменений
```

**Посмотрел рендер глазами**: рамка ниже третьей строки, заголовок читается
целиком.

Тесты: **235 passed** (+2).

## Тест был беззубым, пока я не выразил дефект честно

Первая версия требовала «рамка не ниже текста» — и проходила на HEAD: формально
рамка была ниже на 0.12in, то есть НЕ пересекала текст по числам, хотя на
рендере её граница идёт по выносным элементам «подразделения». Заменил на
требование ЗАЗОРА в 0.25in — того, который синтез сам закладывает под
заголовком. На HEAD падает с
`frame clears the drawn heading by only 0.12in`.

Это третий раз за неделю, когда «числа не пересекаются» и «глаз видит
пересечение» расходятся: важен не факт перекрытия, а зазор.

## Сравнение с прошлой итерацией

iter80 чинила, что харнесс принимает за заголовок; эта — куда заголовок
физически попадает. Четвёртый дефект подряд из пресета `wordy`.
