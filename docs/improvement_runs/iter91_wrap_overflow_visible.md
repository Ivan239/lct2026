# Итерация №91 — рендерный перенос доходит до QA, но чинить его глобально нельзя

## Генерация: пропущена по сети (семьдесят шестой раз подряд), за секунды

Деки от живой модели нет, оценка 10.1 не выставлялась.

## Что увидел глазами

Стат-слайд mono на деке с повтором: заголовок в ТРИ строки, занимает почти
половину слайда, KPI-блок прижат вниз. На соседнем таком же слайде заголовок в
две строки.

## Разбор довёл до общей причины

```
бокс 9.15in, кегль 51pt, бюджет 644pt
«Результаты пилотного» = 535pt → влезает
+ «внедрения»          = 803pt → перенос
строка 2 «внедрения — что дальше» = 616pt при бюджете 644 → по нашей модели ВЛЕЗАЕТ
рендер ломает её раньше → ТРИ строки, 2.45in в боксе 1.88in
```

То есть 616 против 644 — ровно те 2–4%, на которые рендер переносит раньше
(задокументировано с iter64). Для синтеза я это учёл дважды (iter64 — обложка,
iter81 — прочие заголовки), а `enforce_text_fits` меряет без запаса.

## Почему не стал чинить глобально

Замер: если добавить запас в `enforce_text_fits`, под ужатие попадут и авторские
боксы — у нетронутых шаблонов «текст выше рамки» встречается 27–43 раза на деку
ПО ЗАМЫСЛУ (iter61). Правка выглядит однострочной, а задевает чужую вёрстку;
видимого дефекта на сегодняшнем слайде нет (наложения не возникло).

## Что сделал вместо этого

Пробник печатает, сколько НАШИХ боксов переполнится с учётом раннего переноса:

```
обычный бриф: universal 15, study 9, mono 2, survey-31 0
--repeat 3:   universal 29, study 20, mono 5, survey-31 0
```

Первая версия печатала 23 вместо 15 — считала и авторские боксы. Это ровно то, от
чего предостерегает моё же правило «число без названия того, что измерено»:
исправил, теперь текст, совпадающий с шаблонным, не учитывается. Тест проверяет
обе стороны на синтетическом шаблоне.

Тесты: **267 passed** (+1).

## Сравнение с прошлой итерацией

iter90 убрала шум из фикстуры, и на очищенных деках (100.0) стало видно то, чего
раньше не было заметно за флагами дублей. Итог сегодня — не правка поведения, а
ЧИСЛО, по которому такую правку можно будет судить: сейчас «29 наших боксов» —
это гипотеза о риске, а не о видимом дефекте.

## Очередь

1. **[генерация] Запас на рендерный перенос в `enforce_text_fits`** — числа
   собраны; нужен случай, где переполнение даёт ВИДИМЫЙ дефект, иначе правка
   рискует чужой вёрсткой.
2. **[генерация] Ротация цвета на клонах** (iter90) — цвет в полноэкранной
   картинке.
3. **[классификация] Прогон со связью** — потолок survey-31 ~10–12 из 31.
