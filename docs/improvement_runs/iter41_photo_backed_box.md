# Итерация №41 — проверка контраста уверенно врала на тексте поверх фото

## Генерация: пропущена по сети (двадцать шестой раз подряд)

Прогон поднял **GigaChat-3-Ultra × survey-69** и упёрся в OAuth. Деки от модели
нет → **оценку 10.1 и взвешенный итог не выставлял.**

## Первый пункт очереди — проверил и отверг

«Фильтр „есть фото“ отсекает фирменные канвы, теперь его можно ослабить, раз
контент умеет обходить декор (iter38)». Замерил, какие слайды стали бы
кандидатами при условии «картинка оставляет полосу ≥40% высоты»:

```
Универсальный  добавился 1 (сл.5)   Моно  добавились 3   Учебный  добавился 1
```

У Универсального новый кандидат имеет 2 контент-бокса против 5 у текущего
выбора — значит он бы ПОБЕДИЛ. Отрендерил его и посмотрел глазами:

**Текст лёг поверх фотографий.** «Было / Ручной сбор / Разрозненные файлы» —
по розовым пальто, «Стало / Автосбор» — по деревьям. Обход декора не спас:
фотографии по 24% площади, выше порога «мелкий декор» (20%), то есть по замыслу
считаются неизбежным фоном.

Фильтр не трогаю. Посылка пункта умерла ещё в iter40: там канва Универсального
починилась, и лучший из трёх существующих кандидатов теперь честно хорош.

## Что нашёл вместо этого

Прогнал по этому же плохому рендеру харнесс — и он не просто промолчал:

```
'Было|Ручной сбор|…'   None            ← не измерено
'Стало|Автосбор|…'     ratio = 7.40    ← «здоровый» контраст
                       ink=(0,0,0) bg=(208,128,176)
```

7.40 измерено между ЧЁРНЫМИ ДЕРЕВЬЯМИ и РОЗОВЫМ НЕБОМ фотографии. К нашему
белому тексту это отношения не имеет. То есть на тексте поверх картинки
проверка бывает уверенно неправа — ровно тот класс ошибки, на котором проект уже
горел дважды (iter20, iter21).

## Реализация

Признак: какую долю кропа занимает модальный цвет. У бокса с настоящим фоном он
доминирует, у бокса на фотографии — нет. Замер по корпусу:

```
98 реальных текстовых боксов на четырёх деках:  0.70–0.99  (медиана 0.92)
два бокса поверх фото:                          0.02 и 0.34
```

Порог 0.5 с большим запасом с обеих сторон. Ниже него бокс не измеряется вовсе
и уходит в недостающее покрытие — честное «не могу судить» вместо числа.

## Проверка

```
пять дек корпуса + эталон   флаги=[] покрытие 6/6 — без изменений
контроль (невидимый текст)  флаг [4] — по-прежнему ловится
текст поверх фото           ложные 7.40 исчезли; остался 6.58 по chrome-боксам
                            на реальном чёрном фоне
```

Тесты: **153 passed** (+1). Фикстура синтетическая (без LibreOffice) и построена
по механике реального случая: фон из трёх близких оттенков, ни один не
доминирует, плюс крупная тёмная область как «чернила». Она воспроизводит то же
самое число — **7.3966**, — которое выдавал реальный слайд, и падает на HEAD.

## Сравнение с прошлой итерацией

iter40 чинила выбор канвы и дала заметный выигрыш на рендере. Здесь выигрыш
невидим на слайдах: измеритель перестал выдавать уверенно ложный вердикт.
Обе итерации подряд начинались с проверки пункта очереди, который на поверку
оказался неверным, — и обе дали результат из побочного наблюдения.

## Очередь

1. **[классификация] Проверить на сети**, стал ли титул survey-31 «title».
2. **[генерация] Пустой низ** синтезированных слайдов на широких деках.
3. **[harness] Слайд без измеримых боксов** теперь возможен (текст поверх фото).
   Сейчас это просто дыра в покрытии; стоит решить, должен ли такой слайд
   получать пометку «непроверяемо» в отчёте, а не молчание.
4. Пункт 11 плана — по просьбе пользователя не трогаем.
