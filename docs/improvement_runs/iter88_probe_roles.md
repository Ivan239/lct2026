# Итерация №88 — пробник мерил деку не так, как боевой цикл

## Генерация: пропущена по сети (семьдесят третий раз подряд), за секунды

Деки от живой модели нет, оценка 10.1 не выставлялась.

## Пункт очереди привёл к находке рядом

Вчера записал: критерии равномерности штрафуют законно разрежённый дисплейный
слайд. Полез смотреть, как устроено исключение, — и увидел, что оно идёт по РОЛИ
слайда, которую передаёт вызывающий:

```
evaluation/loop.py:  evaluate_deck(..., slide_roles=slide_roles)   ← боевой цикл
scripts/offline_probe.py: evaluate_deck(...)                        ← БЕЗ ролей
```

То есть пробник тридцать пять итераций считал ОБЛОЖКУ и ЗАКРЫТИЕ обычными
контентными слайдами и штрафовал деку за неравномерность ровно за то, что у неё
есть обложка. Это та самая ложная тревога, ради которой исключение и заведено.

Все числа `dop_distribution` / `dop_pacing` в моих отчётах были занижены, а
пробник и цикл нельзя было сравнивать между собой.

## Правка

Пробник передаёт роли — ровно как `loop.py`, из типов блоков плана.

```
обычный бриф:  99.4 → 99.5 (universal, mono, survey-31)
wordy:         93.1 → 93.8 (universal, mono)
--repeat 3:    90.6 → 91.2 (universal), 91.2 → 91.8 (mono, study, survey-31)
CV разброса объёма у Универсального: 0.39 → 0.36
```

Тесты: **260 passed** (+2). На HEAD падает с
`slide_roles was not passed: ['brief', 'label', 'out_json', 'render_dir']`.
Второй тест фиксирует границу: `stats_kpi` в список исключений НЕ входит и не
должен — KPI-доска плотная по замыслу, и освобождение всей роли спрятало бы
настоящую неравномерность.

## Исходный пункт очереди остаётся открытым

Разрежённый слайд «одна большая цифра» по-прежнему штрафуется: у него роль
`stats_kpi`, а она не освобождается. Правильное решение — освобождать не роль, а
СЛАЙД, у которого контент это дисплейная цифра с подписью (признак из iter80).
Не стал делать в одной итерации с находкой выше: сначала пусть пробник и цикл
считают одинаково, иначе следующий замер снова будет несравним.

## Сравнение с прошлой итерацией

iter87 чинила генерацию по пункту очереди; эта пошла по тому же пункту и нашла,
что сам измеритель работал в двух разных режимах. Полезное правило: прежде чем
чинить критерий, проверить, одинаково ли его ВЫЗЫВАЮТ.

## Очередь

1. **[harness] Освобождать дисплейный стат-слайд** от критериев равномерности —
   по признаку слайда, а не по роли.
2. **[классификация] Прогон со связью** — потолок survey-31 ~10–12 из 31.
3. Пункт 11 плана — по просьбе пользователя не трогаем.
