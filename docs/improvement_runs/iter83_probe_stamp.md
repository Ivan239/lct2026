## Системная проверка: доезжает ли бриф до слайдов

Вчерашний дефект (подзаголовок терялся молча) — целый класс, поэтому сверил
КАЖДУЮ строку брифа с текстом деки, по трём пресетам и четырём шаблонам:

```
study, все пресеты: не доехали 2 пары KPI из 3
survey-31, short:   не доехал подзаголовок закрытия
прочее:             всё на месте
```

**Пропажи KPI** — это ёмкость стат-слайда Учебного (один большой показатель),
то есть Пункт 11 плана, который трогать нельзя. Отмечаю и не лезу.

**Подзаголовок survey-31** — оказался НЕ дефектом: я читал `/tmp/probe_short`
от iter72, то есть прогон, сделанный ДО вчерашней правки. На свежем прогоне
подзаголовок на месте.

## Второй раз на одни грабли

Ровно та же ошибка, что в iter72: артефакт, который мог не перезаписаться,
принят за свежий. iter72 чинила половину проблемы — папка чистится при пропуске
и перед генерацией, — но чистка помогает только тем каталогам, которых прогон
касается, а `--out` из прошлой сессии лежит нетронутым.

Поэтому: каждая дека пробника теперь несёт ШТАМП в собственных свойствах файла —
пресет, число пунктов, время и коммит. Штамп едет вместе с файлом, его нельзя
потерять при копировании, и любой замер может спросить, что он читает:

```
свежая: offline_probe content=long items=plan at 2026-08-09T07:50 commit=a915bd5
чужая:  (no stamp)
```

Проверка идёт по МАРКЕРУ, а не по «непустому полю»: python-pptx сам пишет туда
«generated using python-pptx», и первая версия теста на этом упала — она
объявила бы чужую деку штампованной.

Тесты: **243 passed** (+5).
