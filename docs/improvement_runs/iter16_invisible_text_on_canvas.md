# Итерация №16 — невидимый текст на клонированной канве

- **Итерация деки: ПРОПУЩЕНА ПО СЕТИ.** Ротация выдала GigaChat-3-Ultra ×
  `custom_30e96c06e2d47ec3` (31 слайд), разбор дошёл до рендера (31 PNG готов) и
  встал: OAuth-хост `ngw.devices.sberbank.ru:9443` перестал отвечать (ConnectTimeout).
  `api.giga.chat:443` при этом жив — легло только OAuth. Ничего не ломал.
- **Оценка 10.1 за эту итерацию не выставляется** — новой деки нет. Чинил дефект,
  который увидел глазами в прошлой итерации и который был топ-1 в очереди.

## Что чинил

Невидимый текст на слайде-сравнении (Т—Ж Монохромный, прошлая итерация): пункты
покрашены в цвет фона, видны только заголовки. Пиксельный контраст-бэкстоп это не
ловит по построению — текст, слившийся с фоном, не образует «чернильного» кластера.

## Диагноз (по шагам, каждый проверен на файле)

1. Сломанный слайд оказался НЕ родным слайдом шаблона, а **синтезированным**: у
   Т—Ж Монохромного нет родной семьи `two_column_comparison`.
2. Синтез клонирует канву (`_prepare_blank_slide(canvas_idx=...)`) — канва приносит
   СВОЙ фон. А палитра берётся общедековая, и вето по контрасту в `deck_style`
   сравнивает цвет текста с фоном БОЛЬШИНСТВА слайдов (белым), а не с фоном канвы.
   Отсюда: одобренный «синий на белом» попадает на синюю канву и исчезает.
3. **Первая версия фикса (по XML) НЕ РАБОТАЛА — поймал проверкой.** `_slide_bg_hex`
   читает только `a:srgbClr`, а у этого шаблона все слайды объявляют
   `<a:schemeClr val="lt1"/>`. Хуже: тема мапит `lt1` в `#FFFFFF`, тогда как рендер
   показывает четыре слайда сплошь синими. Ровно предупреждение CLAUDE.md — «тема
   OOXML часто врёт про реальный вид деки». Замер по рендерам:
   слайды 0/4/8/10 → `(32,56,248)`, остальные → `(248,248,248)`.
4. Поэтому фон берётся ИЗМЕРЕННЫЙ (`style_profile.build_measured_profile`), который
   цикл и API уже считают для ротации цветов.

## Что реализовано и ПРОВЕРЕНО РЕНДЕРОМ + ГЛАЗАМИ

- `synthesizer._recolor_for_canvas(palette, canvas_bg)` — при |Δ яркости| < 80
  переключает `text`/`accent` на белый/почти-чёрный. Принимает измеренный RGB
  (основной путь) или hex; `None` → палитра не трогается. Брендовый цвет, который
  реально контрастирует, сохраняется.
- Плюмбинг измеренных фонов: `generate(..., canvas_backgrounds=...)` →
  `SYNTHESIZERS[...](..., canvas_bg=...)`; передаётся из `evaluation/loop.py`
  (`profile["backgrounds"]`) и из `api/main.py` (новый `_measured_backgrounds`).
- Проверка ОФЛАЙН (сеть лежала, но сборка деки GigaChat не требует): вручную
  собранный `two_column`-слайд на синей канве (слайд 4 реального шаблона) —
  посмотрел рендер глазами: **весь текст белый и читается**, тогда как раньше
  пункты были невидимы.
- Тесты: **114 passed**.

## Сравнение с прошлой итерацией

Прошлая закрыла краш `KeyError: image_caption` на реальном шаблоне. Эта закрыла
топ-1 дефект из её очереди — невидимый текст. Обе вскрылись только на настоящих
шаблонах.

## Очередь

1. **[harness, высокий] Бэкстоп не видит невидимый текст** — нужна проверка
   объявленных цветов ранов против ИЗМЕРЕННОГО фона слайда (пиксельная бессильна).
   Теперь для этого есть готовый кирпич — измеренные фоны прокинуты в генерацию.
2. **[средний] Узкие колонки на синтезе** — на проверочном рендере «Разрозненность»
   переносится по слогам в 3 строки; ширина колонок берётся из bounds канвы без
   учёта длины заголовков.
3. Ранее записанное: ложные срабатывания контраста на card-style Т—Ж, служебный
   текст шаблона, устаревшие номера слайдов, рамка-скелет за границей слайда.
4. Незавершённое: прогон Ultra × 31-слайдовой деки (упал по сети) — повторить.
