# Модели

## Требование кейса

> Генеративные модели: только с открытыми весами и лицензией Apache 2.0 / MIT.
> LLM/VLM/text-to-image до 35B. На отборочном этапе команда обеспечивает инференс
> самостоятельно — на собственном GPU или через внешнего API-провайдера.

Сервис исполняет это требование конфигурацией: провайдер задаётся тремя
переменными окружения, код ни к какому вендору не привязан — весь текстовый
пайплайн работает через OpenAI-совместимый `/chat/completions`.

```bash
LLM_BASE_URL=https://<ваш-эндпоинт>/v1
LLM_MODEL=Qwen/Qwen2.5-32B-Instruct
LLM_API_KEY=<если требуется>
```

При старте API печатает, на какой модели он работает:
`[api] генератор: Qwen/Qwen2.5-32B-Instruct через https://…/v1`.

## На чём собрано решение (для экспертов)

| Что | Значение |
|---|---|
| Сервис | [Cloud.ru Evolution Foundation Models](https://cloud.ru/products/evolution-foundation-models) — российский провайдер, OpenAI-совместимый API, оплата в рублях |
| Endpoint | `https://foundation-models.api.cloud.ru/v1` |
| Модель | [`Qwen/Qwen3-32B`](https://huggingface.co/Qwen/Qwen3-32B) — 32.8B, открытые веса, **Apache 2.0** |
| Настройки | `temperature` и `top_p` — умолчания провайдера (в запросе не передаются); `max_tokens` 300–1600 по типу вызова; `LLM_VERIFY_SSL=1` |
| Режим рассуждений | не включается; если модель всё же пришлёт `<think>…</think>`, он отрезается до разбора JSON (`common/json_utils.py`) |
| Время | колода в 10–15 слайдов — 30–75 с вместе с вёрсткой и рендером (лимит кейса — 5 мин) |
| Стоимость | ~37 ₽ за 1М входных и ~148 ₽ за 1М выходных токенов: колода обходится в единицы рублей |

Все девять колод сдачи (`scripts/make_submission.py`: 3 варианта вёрстки × 3
шаблона) и прогон на видео сделаны на этой конфигурации:

```bash
LLM_BASE_URL=https://foundation-models.api.cloud.ru/v1
LLM_MODEL=Qwen/Qwen3-32B
LLM_API_KEY=<API-ключ Cloud.ru Foundation Models>
```

Ключ в репозиторий не кладётся (`.env` в `.gitignore`). Чтобы воспроизвести,
нужен свой API-ключ Cloud.ru — или любой другой endpoint с открытой моделью
до 35B, правок кода это не требует.

## Чем проверено и что рекомендуется

| Модель | Параметры | Лицензия | Роль в пайплайне |
|---|---|---|---|
| [Qwen3-32B](https://huggingface.co/Qwen/Qwen3-32B) | 32.8B | Apache 2.0 | **основная**: план колоды и текст блоков (Cloud.ru) |
| [Qwen2.5-32B-Instruct](https://huggingface.co/Qwen/Qwen2.5-32B-Instruct) | 32B | Apache 2.0 | для самостоятельного хостинга через vLLM |
| [Qwen2.5-14B-Instruct](https://huggingface.co/Qwen/Qwen2.5-14B-Instruct) | 14B | Apache 2.0 | экономичный режим, когда важна скорость |
| [Mistral-Small-24B-Instruct](https://huggingface.co/mistralai/Mistral-Small-24B-Instruct-2501) | 24B | Apache 2.0 | альтернатива с тем же интерфейсом |

Для топ-10 кейс предусматривает инференс VK с Qwen 3.8 27B — он подключается той
же переменной `LLM_BASE_URL`, правок кода не требуется.

### Системные требования для самостоятельного хостинга

| Модель | Точность | VRAM | Комментарий |
|---|---|---|---|
| Qwen2.5-32B-Instruct | AWQ/GPTQ 4-bit | ~24 ГБ | одна A100 40G или 2×3090 |
| Qwen2.5-32B-Instruct | bf16 | ~70 ГБ | 2×A100 40G |
| Qwen2.5-14B-Instruct | 4-bit | ~10 ГБ | одна 3090/4090 |

Запуск через vLLM: `vllm serve Qwen/Qwen2.5-32B-Instruct --port 8000`, дальше
`LLM_BASE_URL=http://localhost:8000/v1`.

## Где именно вызывается модель

Вызовов всего два вида, остальное — детерминированный код.

1. **Классификация слайдов шаблона** (`design_system/extractor.py`) — один вызов
   на кластер похожих слайдов, а не на слайд. У шаблона в 54 слайда это 8–12
   вызовов вместо 54. Результат кэшируется по геометрическому отпечатку слайда с
   версией классификатора (`fingerprint_cache.CLASSIFIER_VERSION`), поэтому
   повторный разбор того же шаблона не стоит ничего.
2. **Генерация контента** (`content_parser/two_phase.py`) — план колоды одним
   вызовом плюс по вызову на блок; на короткий план один добор, на слишком
   длинные пункты один корректирующий вызов.

Дополнительно один вызов на шаблон делает «стиль-карта» (`design_system/style_card.py`) —
словесный дизайн-бриф шаблона; результат кэшируется на диск с версией.

**Стоимость генерации.** На колоду в 10–15 слайдов приходится 12–18 вызовов
модели, преимущественно короткие ответы (один блок слайда — 100–200 токенов).
Разбор шаблона оплачивается один раз на шаблон, а не на генерацию: именно
поэтому в кейсе разбор вынесен за рамки пятиминутного лимита, и у нас он тоже
кэшируется.

## Версионирование промптов и скиллов

Требование ТЗ «промпты и конфиги скиллов лежат отдельными файлами, не зашиты в
код» выполнено: всё в `prompts/`, версия в имени файла.

| Файл | Назначение |
|---|---|
| `outline.v1.txt` | план колоды |
| `outline_more.v1.txt` | добор недостающих блоков |
| `block_<роль>.v1.txt` (7 файлов) | текст блока под конкретную роль |
| `shorten_items.v1.txt` | переписать слишком длинные пункты |
| `classify_slide_text.v1.txt`, `classify_slide_vision.v1.txt` | классификация слайда шаблона |
| `style_card.v1.txt` | дизайн-бриф шаблона |
| `schema_blocks.v1.txt`, `title_for_block.v1.txt`, `resize_block.v1.txt` | легаси-путь планирования |

Правка файла промпта — это новая версия: она обязана поднять версию кэша
(`CLASSIFIER_VERSION`, `STYLE_CARD_VERSION`), иначе закэшированные ярлыки будут
вечно переигрывать старый промпт. Тест `test_no_prompt_is_left_inline` не даёт
завести новый промпт внутри кода.

## Честно о ходе разработки

Итерационный цикл улучшений (150+ прогонов, журнал в `improvement_runs/`) шёл на
доступном команде провайдере — GigaChat: он использовался как генератор текста,
пока настраивался собственный инференс. Код от него не зависит: клиент
GigaChat остаётся в репозитории только как запасной путь разработки и
включается, лишь если `LLM_BASE_URL` не задан. Для сдачи и демонстрации сервис
работает на `Qwen/Qwen3-32B` через Cloud.ru (см. «На чём собрано решение»).

Vision-модели в продукте не используются: классификация слайдов идёт по
структуре (типы фигур, их геометрия, абзацы), а не по картинке — это дешевле и
не требует мультимодальной модели. Контраст текста к фону измеряется по
пиксельному рендеру арифметически, без модели.

Генерация изображений внутри слайда (text-to-image ≤20B) — задача со звёздочкой
для топ-10; сейчас на месте картинки рисуется рамка-скелет с описанием сюжета.
