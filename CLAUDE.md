# СлайдоГен

AI-генератор презентаций (хакатон, 2 мес, коммерческий прицел, импортозамещение).
Разбирает корпоративный PPTX-шаблон → кластеризует слайды на архетипы → по брифу
генерирует новую презентацию в стиле шаблона через GigaChat. Выход — обычный .pptx.

## Запуск

- Backend: `.venv/bin/uvicorn src.api.main:app --app-dir . --port 8000` (без --reload — после правок перезапускать).
- Frontend: `cd frontend && npm run dev` (Vite, порт 5173).
- Оценка + цикл улучшения: `.venv/bin/python3 scripts/improve_loop.py --model auto`
  (генерит деку по каноническому брифу, гоняет ДЕТЕРМИНИРОВАННЫЕ проверки без
  токенов, пишет JSON в `output/evaluations/`, печатает пути рендеров). Рубрика —
  `docs/evaluation_rubric.md`; харнесс — `src/evaluation/` (rubric-веса +
  гео/типографика-проверки + render-based contrast). **LLM-критерии (композиция,
  тон, галлюцинации и т.п.) НЕ оцениваются никаким API-вызовом** — GigaChat-vision
  как судья был измерен и оказался плохим (деку с дублирующимися stats-слайдами и
  пустыми нижними половинами почти всех слайдов оценил в 90+/100; пользователь на
  тех же рендерах дал 3-4/10). Судья теперь — Claude: смотрит на рендеры (Read) и
  выставляет оценки через `evaluation/claude_review.py::apply_claude_scores`
  (CLI — `scripts/claude_score.py --eval <json> --scores '{"1.3":[2,"..."]}'`).
  Итоговый взвешенный балл — композит по ~30 критериям, он НЕ обязан совпадать с
  цельным впечатлением «показать не стыдно?» (это отдельный критерий 10.1).
  Бэкенды моделей-генераторов — `src/llm_clients/backends.py` (RTX = обучающая
  видеокарта, в очереди, не инференс-бэкенд). Отчёты итераций — `docs/improvement_runs/`.
- Тесты: `.venv/bin/python3 -m pytest tests/ -q` — быстрые, без LLM и без LibreOffice; гоняй после каждого изменения генератора/кластеризации.
- Рендер для проверки: `src/rendering/render.py::render_pptx_to_pngs` (LibreOffice + pdftoppm; отсутствующие шрифты подменяются на Arial только в превью-копии).

## Пайплайн (src/)

`template_parser` (OOXML → структура) → `design_system/clustering.py` (дистанционная
кластеризация: Dice по мультисетам фигур + мягкий визуальный штраф по рендерам;
LLM-классификация один раз на медоид кластера, рыхлые кластеры (spread≥0.2)
пробятся 2 дальними членами и при расхождении расклеиваются поштучно; межшаблонный
кэш `design_system/fingerprint_cache.py` с CLASSIFIER_VERSION) →
**Template Style Profile** (`design_system/style_profile.py` — палитра фонов из
рендеров, инференс ротации цветов, bookends, breathers; НЕ кэшируется; +
`style_card.py` — 1 LLM-вызов на шаблон, версионированный кэш `parsed/{id}_style.json`,
преамбула в промпты) → `template_spec/builder.py` (слоты/ёмкости + bg-цвет члена
семьи + rotation; НЕ кэшируется на диск) → `content_parser/two_phase.py` (outline →
блоки под конкретную ёмкость, со стайл-преамбулой) → `matcher` (слайд выбирается ДО
генерации текста; ёмкость → цвет ротации → round-robin; closing может клонировать
использованный слайд ради брендового bookend) → `generator/generator.py` (заполнение;
слот-боксы; повторы клонируются через `slide_kit.clone_slide`; синтез отсутствующих
ролей — на клон-канве `synth_canvas` с фоном/шапкой шаблона; chrome-фильтр служебных
боксов) → `qa/geometry.py` (ужатия/гармонизация) → `qa/package_check.py`
(структурный аудит + вендоренный ISO-валидатор `vendor/ooxml_validator`; битый
пакет не отдаётся никогда).

## Выученные правила (нарушение = регрессия)

- Жёсткие ограничения (количество пунктов, обязательный title, максимум дивайдеров)
  энфорсить кодом с валидацией и ретраями — модель НЕ следует формулировкам промпта.
- `get_capacity` обязана зеркалить порядок выбора фигур соответствующего филлера
  (body до title!) — расхождение даёт занижение ёмкости и «пустые» слайды.
- Повторяющиеся роли в пробнике обязаны нести РАЗНЫЙ контент, иначе критерии
  дублей срабатывают на фикстуре (деки с `--repeat` показывали 91–92 и «слабые:
  2.3, dop_no_dup_slides» только поэтому; с разным контентом — 100.0). Различие
  делать заменой пунктов, а НЕ суффиксом: суффикс срезает бюджет слота, и слайды
  остаются одинаковыми под разными заголовками.
- План для проверки собирать ТОЛЬКО через `offline_probe.build_plan`: ручная
  сборка трижды разошлась с боевой и дала мираж (iter42 — забыт `count`, iter56
  и iter85 — забыты бюджеты символов; во втором случае рендерный autofit был
  принят за дефект продукта). Повтор ролей (`--repeat`) — единственный способ
  дойти до клон-пути; на реальных шаблонах он цел (audit/validate чисты).
- Фиксы проверять на реальных файлах из `output/templates/` рендером и инспекцией
  python-pptx, не заявлять теоретически. НЕ тратить токены GigaChat на массовые
  проверочные генерации («не делая 4 презентации»); классификация/кластеризация/спека
  проверяются вообще без LLM.
- Тексты у Google-Slides-экспортов часто без явного размера шрифта — эвристика
  «титул = максимальный размер руна» слепа к ним; всегда предпочитать нативные
  плейсхолдеры из XML. Фолбэк без плейсхолдеров — НЕ голый максимум шрифта:
  на стат-слайдах KPI-числа (48pt) крупнее титула (30pt), и титул уезжает в
  номерной бокс, сдвигая все пары число/лейбл; шейпы ниже верхней четверти
  контентного диапазона штрафуются ×0.5 (`_pick_title_shape`).
- Синтезированные слайды и стат-/колоночные блоки не прижимать к заголовку:
  контентная группа центрируется по вертикали в остатке inferred bounds по
  оценённой высоте (`synthesizer._centered_top`), переполнение → без сдвига.
- Тема OOXML часто врёт про реальный вид деки (ручные деки красят раны напрямую,
  theme1.xml — офисный дефолт): синтез берёт стиль из `deck_style.observe_deck_style`
  (голосование по слайдам) с вето по контрасту. Ловушки: фон читать из сырого XML —
  `slide.background.fill` мутирует деку при чтении (get-or-add); имена шрифтов
  `+mj-lt`/`+mn-lt` — токены темы, в run.font.name их писать нельзя.
- `.paragraphs`/`.runs` в python-pptx — кортежи; пустые проверять до индексации.
- Процентный межстрочный интервал (spcPct) рендеры считают как 1.2 × размер ×
  процент, НЕ от метрик шрифта (`text_fit.paragraph_pitch_pt`); фиттинг обязан
  учитывать line_spacing и tIns/bIns, иначе LO молча ужимает через normAutofit
  и все позиции, посчитанные от нашего размера (иконки), устаревают. Любое
  пост-QA ужатие шрифта — перекладывать иконки (`_realign_icons_after_resize`).
- `pptx.util.Length` — подкласс `int`: в ветвлениях «процент vs абсолют»
  проверять `isinstance(x, Length)` ДО `isinstance(x, (int, float))`.
- Бюджет ширины текста считать от РЕАЛЬНЫХ горизонтальных полей: lIns/rIns
  бокса + абзацный marL/indent (`text_fit.horizontal_margins_in`), не от плоских
  0.2". У иконочных списков lIns=0 + rIns=0.1" + marL=0.25" — плоская оценка
  съедала почти весь 5%-запас «гарантии одной строки», и рендер переносил
  пункт, разваливая колонку иконок (боевая дека f78f14b1, слайд 2).
- Рендер переносит строки на ~2-4% раньше, чем предсказывают fontTools-метрики
  (замерено: строка 418.6pt перенеслась в боксе с бюджетом 428pt). Предсказывать
  перенос на таких полях нельзя; для списков с иконками-маркерами шрифт
  подбирается так, чтобы каждый пункт гарантированно был одной строкой с запасом
  5% (`text_fit.fit_font_size_single_line`, `prefer_single_line=True`), фолбэк на
  переносы — только для аномально длинных пунктов.
- Списки заполнять по СЛОТАМ контента (абзацы с текстом шаблона), не в
  paragraphs[0..N]: ручные деки разделяют пункты пустыми абзацами-спейсерами.
  Лишние абзацы после последнего пункта УДАЛЯТЬ физически, а не чистить —
  очищенный абзац остаётся пустой строкой (а «пустой» ран из '\x0b' — тремя),
  фантомные строки переполняют бокс и LO молча ужимает текст через normAutofit,
  смещая иконки. Спейсеры между пунктами нормализовать до минимального зазора
  шаблона, marL/indent пунктов унифицировать (мажоритарный), иконки шагают по
  ВСЕМ абзацам включая спейсеры. Эталон дефекта: слайд 2 custom_78dc579e05d11399
  (слоты 0/3/5/7, спейсеры, хвост с '\x0b\x0b\x0b'). Тесты: test_slot_fill.py.
- Детект «текст поверх КАРТИНКИ» не делать ни по рамкам (iter53), ни по полосам
  текста (iter86): на слайде 8 Универсального собственная цифра дизайнера
  перекрывает арт на 0.70 — столько же, сколько наш нечитаемый заголовок. Долей
  их не различить, различает только контраст под глифами; там, где он не
  измерим, харнесс обязан назвать ПРИЧИНУ (`unmeasured_why`).
- Порог «свободная зона уже 40% ширины бокса — не сужать» (iter71) НЕ ослаблять:
  замер показал, что сужение до узких колонок выталкивает текст за край слайда
  (9.1 = 1, итог 91.9 → 86.9).
- Детект пересечений текстбоксов ПО ПРЯМОУГОЛЬНИКАМ не делать: у дизайнеров
  боксы пересекаются по дизайну (51 срабатывание на нетронутом 69-слайдовом
  оригинале) — см. заметку в qa/geometry.py. По ПОЛОСАМ ТЕКСТА — можно и нужно:
  замер по 217 авторским слайдам даёт максимум 0.51 (survey-69 намеренно
  подсовывает сноску под вопрос), а настоящий дефект (подзаголовок внутри титула)
  — 1.00; порог 0.7 разделяет их с запасом (`deterministic._text_collisions`).
- В описании слайда для классификатора текст бокса НЕ склеивать: у survey-31
  контентные слайды это «титул + один бокс», а в боксе 4/5/7/8 отдельных абзацев
  (иконочные списки). Склейка в одну строку отбирала признак списка, и разбор
  выходил 1 слайд из 31. Показывать число абзацев и первые из них порознь
  (`extractor._describe_slide`), не забыв бампнуть CLASSIFIER_VERSION.
- layout_name — шум экспортёра ВЕЗДЕ, не только в кластеризации: в описании
  слайда для LLM-классификации строка «Layout: TITLE» (Т-Ж вешает такой layout
  на все слайды) перевешивала фактическую структуру — буллет-лист из 5 боксов
  уверенно шёл в «title»; без строки — уверенно в «bullet_list». Layout в
  промпт не включать (`extractor._describe_slide`).
- Если у слайда НЕТ второго бокса, подзаголовок не выбрасывать, а класть
  ОТДЕЛЬНЫМ шейпом под титулом (как подпись показателя в iter70). Вторым абзацем
  в бокс титула — нельзя: харнесс читает заголовок как весь текст бокса, и пара
  превращается в «длинный заголовок». Новый шейп обязательно добавить в
  `claimed_ids`, иначе `_clear_unclaimed_text` его обнулит.
- Если верхний контентный бокс стат-слайда — ПОКАЗАТЕЛЬ, титульного слота на
  слайде нет (`_stats_title_shape` → None): у Универсального макет «цифра 92pt +
  подпись», и наш заголовок, занимая слот цифры, шёл поперёк арта нечитаемо.
  Цена — заголовок из брифа на такой слайд не попадает; выдумывать ему место
  поверх арта нельзя.
- ПОКАЗАТЕЛЬ («-40%», «20 227 000») — не заголовок, как бы крупно ни был набран:
  позиционного штрафа ×0.5 не хватает, когда цифра идёт шаблонным кеглем (72pt
  против 18pt титула). Признак — «половина непробельных символов цифры и знаки»,
  а НЕ «коротко и есть цифра»: под второе попадает «Top 7», настоящий заголовок
  реального шаблона. Штраф, а не дисквалификация: если других кандидатов нет,
  цифра остаётся заголовком.
- ЗАГОЛОВОК сверх бюджета слов резать по границе клаузы (перед союзом, после
  запятой), беря самую позднюю в пределах лимита; нет границы — оставлять
  ЦЕЛЫМ. Плоское `words[:9]` дало «…и без ручной» — предлог с прилагательным без
  существительного на самом заметном тексте слайда. Многоточие тут неуместно
  (титул не должен выглядеть сокращённым), а длинный титул ужмётся сам.
- Шаблонный кегль титула верен для СОБСТВЕННЫХ титулов шаблона: длинный
  заголовок при нём разворачивается на четыре строки и занимает 62% слайда
  (у шаблонов медиана 8–23%), а контент под ним сжимается в полоску. Ужимать,
  пока титул не уложится в 40% контентной полосы (`_TITLE_MAX_BAND_SHARE`).
- Обрезанная фраза должна ВЫГЛЯДЕТЬ обрезанной: бегущая шапка резалась по 42
  символам и давала «ЕДИНАЯ ПЛАТФОРМА УПРАВЛЕНЧЕСКОЙ» — прилагательное без
  существительного, и так на каждом слайде. Многоточие + сброс висящего предлога
  (`_shorten_running_topic`). Общее правило про предлоги живёт в
  `common/phrases.py`: generator НЕ может импортировать two_phase — цикл через
  `template_spec.builder`.
- Удалив чужой график, ЗАКРЫТЬ дыру: дизайнер ставит итоговый абзац ПОД
  графиком, и после удаления слайд выходит «заголовок — пустота 2.70in — три
  строки у нижнего края». Поднимать только то, что целиком ниже картинки, и не
  выше зазора под тем, что кончается сверху (`_close_hole_left_by`).
- Картинка, чьи БАЙТЫ повторяются на нескольких слайдах шаблона, — брендовый
  арт, а не данные слайда: график делается под свой слайд и уникален. Замер по
  138 крупным картинкам корпуса: повторяются ровно 4, все — иллюстрация
  «обложка + контакты» survey-дек, которую иначе вырезали бы. Пиксельные признаки
  тут бессильны: у плоской иллюстрации 8 оттенков, у МОНОХРОМНОГО графика — 9.
  Предпочитать структурные признаки (что документ заявляет) пиксельным (на что
  картинка похожа).
- «Большая картинка → слайд в other» различает ДАННЫЕ и ДЕКОР
  (`common/pictures.py::is_stale_data_picture`): фон, на котором ЛЕЖАТ
  текстбоксы слайда (папки Т-Ж, площадь ~100%) и фото (dom_share<0.6) — декор,
  оставлять; график/скриншот (плоский почти-белый доминант ≥0.6, sat≤0.15,
  стоит ОТДЕЛЬНО от текста) — чужие данные, исключать. Старое правило «только
  по площади» выкидывало 11 из 12 слайдов иллюстративного шаблона.
- Кэш фингерпринтов ВЕРСИОНИРОВАТЬ (`fingerprint_cache.CLASSIFIER_VERSION`):
  bump при любом изменении промпта/описания/линейки моделей классификации,
  иначе старые ярлыки переигрываются молча — Т-Ж дважды «переклассифицировался»
  с нулём LLM-вызовов, честно воспроизводя ошибки самого первого прогона.
- FastAPI-эндпоинты с долгой блокирующей работой (разбор шаблона, генерация)
  объявлять обычным `def` (уходит в threadpool), НЕ `async def`: async с
  синхронной начинкой замораживает весь event loop — /api/progress и все
  остальные запросы висят до конца операции (реально пойманный баг).
- Удаление слайда из `prs.slides._sldIdLst` НЕДОСТАТОЧНО — снимает слайд из
  видимого списка, но физическая часть (slideN.xml) и связь в
  presentation.xml.rels остаются в пакете: валидный zip, валидный XML, но
  PowerPoint это открывает с «требуется восстановление» (сирота — часть,
  на которую есть связь, но которой нет в sldIdLst). Обязательно ещё
  `prs.part.drop_rel(sldId.get(qn("r:id")))` на КАЖДЫЙ убираемый sldId —
  `Package.iter_parts()` (что реально пишется в файл) идёт по достижимости
  от связей, так что сама часть исчезнет из сохранения автоматически, без
  отдельного шага «удали ещё и файл». Реальный баг: ловилось на любой деке,
  где план переиспользовал роль (путь клонирования) — т.е. на шаблонах с
  малым числом нативных слайдов на семью это было ВСЕГДА, не через раз.
- У клонирования (`_clone_slide`) была ВТОРАЯ, независимая причина того же
  «требуется восстановление» — нашлась только когда первый фикс не помог.
  Копировались ВСЕ связи исходного слайда, включая notesSlide — а эта часть
  подразумевает владение РОВНО одним слайдом (обратной связи notes→slide нет,
  владение = единственное ребро). При N клонах одного слайда N+1 разных
  слайдов объявляли ОДНУ И ТУ ЖЕ notesSlide-часть своей. slideLayout и
  notesSlide — оба «единоличные» реltype и должны исключаться при
  копировании связей клона; image/hyperlink можно и нужно шарить (это
  нормально в OOXML). Урок: если фикс «не помог» — не первый ли фикс был

  (лишняя строка вне бокса), «смотреть НИЖЕ бокса» кричит на здоровых деках
  (там текст следующего бокса). Работает «упирается ли текст в НИЖНИЙ КРАЙ
  своего бокса» — и только на СИНТЕЗИРОВАННЫХ слайдах: на нативных бокс
  дизайнерский, а у него текст выходит за рамку по замыслу.
- ЖИРНЫЙ текст мерить жирной гарнитурой: метрики резолвятся по имени семейства,
  то есть по обычному начертанию, а кириллица жирным шире на 7–8% (замер по
  Arial 40pt: 796→858, 630→682, 914→977pt). Титул «Что мешало собирать
  отчётность вовремя» при бюджете 853pt по обычным метрикам «однострочный», а
  рендер даёт две строки, и бокс титула выходит короче нарисованного — всё, что
  ставится ниже, промахивается. `metrics_for(name, bold=True)`; плоский
  `BOLD_WIDTH_FACTOR=1.05` остаётся только для пути без метрик.
- Слабина компоновки ПРЯЧЕТ дефекты модели: наложение первого пункта на вторую
  строку заголовка существовало всегда, но было невидимо, пока центрирование
  отодвигало контент. Отменённая правка, высветившая дефект, полезнее принятой.
- Падение синтезированного блока ограничено зазором, ЗАМЕРЕННЫМ у шаблона
  (`_template_content_gap_in`: 0.00/0.06/0.20/0.25/1.12in на пяти реальных) —
  не «центрировать всегда» и не «прижимать всегда»: центрирование отрывало
  заголовок от контента (наши 14–21% против шаблонных 0–4%), а плоское
  прижатие сломало бы mono, который держит контент низко сам. Решение принято
  сравнением ДВУХ рендеров одной деки и только ПОСЛЕ починки метрик жирного —
  на кривой модели сравнивать было нечего. `test_synth_center` держит оба
  случая и историю обоих решений.
- Канва шаблона — СЕТКА слотов, и заполнить один бокс, обнулив остальные, значит
  сохранить пропорции и потерять дизайн: у mono сетка «01 — текст» на 6 слотов
  отдаёт 2 заполненных, у Универсального 2 из 5, и на рендере это заголовок с
  одинокой строкой в углу. Харнесс этого НЕ ВИДЕЛ (геометрия чиста, разрежённые
  слайды исключены из равномерности, итог 99.5) — печатается пробником как
  «слотов канвы N/M (слайд K)».
- Правка, верная ГЕОМЕТРИЧЕСКИ, может быть вредна визуально: ограничение сдвига
  `_align_left_edges` вернуло тело в свою колонку — и текст повис посреди
  пустого слайда, потому что соседние слоты обнулены. Пока чинится следствие,
  неверное положение может случайно спасать слайд; смотреть рендер, а не только
  координаты.
- Измеритель обязан мерить то, что написано на его ИМЕНИ: «переполнится при
  рендерном переносе» считал «оценка выше рамки» и завышал в 15 раз — 13 из 15
  боксов Универсального были ОДНОСТРОЧНЫМИ с промахом 0.01in (8pt «2025» в
  0.12in, 24pt «-40%» в 0.36in): дизайнер верстает бокс по высоте прописной, и
  переносить там нечего. Считать только те боксы, которым безопасная ширина
  стоит ЛИШНЕЙ строки против полной, и мерить КАЖДЫЙ абзац своим кеглем (общий
  max переносил подпись 11pt как 24pt).
- Ширину текста мерить в том виде, в каком его ОТРИСУЮТ: если запись применяет
  `.upper()` (бегущая шапка берёт регистр у шаблонного плейсхолдера), замер по
  исходному регистру врёт — кириллица капсом шире, «ПЛАТФОРМА УПРАВЛЕНЧЕСКОЙ…»
  вышла 137pt при бюджете 133 и всё равно переносилась.
- Проверяя тест на HEAD, откатывать ТОЛЬКО код: `git stash` без пути уносит и
  сам тест — файл проходит «зелёным», потому что нового теста в нём нет.
- Измеритель, который МОЛЧИТ, читается как «проверено, всё хорошо». Контраст на
  тексте поверх картинки не измерим (фона нет) — и обязан быть назван в отчёте
  (`unmeasured_boxes`), иначе харнессу доверяют там, где он слеп. Тот же мотив,
  что у `coverage` в объявленной проверке.
