# СлайдоГен — цифровой дизайнер презентаций

Сервис собирает готовую презентацию в чужом корпоративном шаблоне по текстовому
брифу: разбирает загруженный `.pptx`, извлекает из него дизайн-систему и набор
макетов, планирует структуру колоды, наполняет слайды текстом и проверяет
результат встроенным аудитом. На выходе — обычный `.pptx` с нативными объектами
(не картинка слайда).

Решение задачи №4 VK Tech, хакатон «Лидеры цифровой трансформации 2026».

## Что умеет

- **Импорт и декомпозиция шаблона.** Любой `.pptx`: слайды кластеризуются по
  структуре, каждому кластеру присваивается архетип (обложка, список, доска
  показателей, сравнение, разделитель, картинка с подписью, закрытие). Из
  рендеров вынимается палитра фонов, ротация цветов и типографика.
- **Планирование колоды.** По брифу и назначению (фича, проект, инициатива)
  строится план: состав слайдов, их порядок и содержание — до вёрстки.
- **Вёрстка в шаблоне.** Текст раскладывается по слотам конкретного слайда с
  учётом реальных метрик шрифта: подбор кегля, переносы, бюджеты длины пунктов,
  выравнивание, чистка авторских заглушек.
- **Аудит.** Около 30 детерминированных проверок геометрии, типографики,
  палитры и содержания; находки показываются вместе с результатом, пользователь
  отмечает, какие исправить, — сервис переписывает только эти слайды и проверяет
  колоду заново. Выдуманные числа отсекаются ещё при генерации.
- **Контент-пакет.** Папка или zip с брифом, фактами, таблицами и картинками
  импортируется целиком; цифры из фактов служат эталоном для проверки
  «все числа со слайда есть в исходных материалах».

## Ограничения

- Изображения внутри слайда не генерируются (задача со звёздочкой, только для
  топ-10). Поэтому без картинки сервис не планирует слайд «картинка + подпись» и
  не берёт слайды шаблона, построенные вокруг демо-картинки в слоте (мокап
  телефона): пустых рамок в готовой колоде нет.
- Нативные графики и таблицы пока не собираются: слайды шаблона, построенные
  вокруг чужой диаграммы или таблицы, из подбора исключаются, чтобы не выдать
  данные дизайнера за свои.
- Экспорт — три формата: `.pptx` (нативные редактируемые объекты — основной),
  `.pdf` и `.html` (для просмотра; HTML — один самодостаточный файл, текст
  слайдов в нём настоящий, а не картинка). PDF и HTML строятся из рендера
  LibreOffice: если шрифтов шаблона нет на сервере, в них подставляется Arial
  (в Linux-образе — метрически совместимый Liberation Sans), и сервис прямо
  называет заменённые шрифты; в `.pptx` шрифты всегда оригинальные.
- Интерфейс рассчитан на десктопные браузеры (Chrome, Firefox, Safari, Яндекс).

## Быстрый старт (Docker, рекомендуется)

```bash
cp .env.example .env          # вписать доступы к инференсу
docker compose up --build
```

- UI: http://localhost:5173
- API: http://localhost:8000

В образ уже входят LibreOffice и poppler-utils — они нужны для рендера превью
слайдов и без них сервис поднимется, но не покажет картинки слайдов.

## Запуск без Docker (Ubuntu 22.04 / Debian 12)

```bash
# системные зависимости: рендер превью
sudo apt-get update
sudo apt-get install -y python3.12 python3.12-venv libreoffice poppler-utils fonts-dejavu

# бэкенд
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
set -a; . ./.env; set +a
.venv/bin/uvicorn src.api.main:app --app-dir . --host 0.0.0.0 --port 8000

# фронтенд (во втором терминале)
cd frontend
npm ci
npm run dev -- --host          # http://localhost:5173
```

Продакшен-сборка фронта: `npm run build`, статика кладётся в `frontend/dist`.

### Переменные окружения

| Переменная | Назначение | Обязательна |
|---|---|---|
| `LLM_BASE_URL` | OpenAI-совместимый endpoint модели с открытыми весами | да |
| `LLM_MODEL` | имя модели на этом endpoint (решение сдано на `Qwen/Qwen3-32B`) | да |
| `LLM_API_KEY` | ключ провайдера, если он требуется | нет |
| `LLM_VERIFY_SSL` | `0` — не проверять TLS (только для локального vLLM с самоподписанным сертификатом) | нет |
| `GIGACHAT_CLIENT_ID` / `GIGACHAT_CLIENT_SECRET` | запасной провайдер, использовался при разработке | нет |

**На чём собрано решение:** Cloud.ru Evolution Foundation Models,
`https://foundation-models.api.cloud.ru/v1`, модель `Qwen/Qwen3-32B` (открытые
веса, Apache 2.0). Подробности о моделях, настройках и лицензиях — в
[docs/MODELS.md](docs/MODELS.md).

## Как пользоваться

1. Загрузить шаблон `.pptx` — сервис разберёт его (разбор кэшируется, на время
   генерации не влияет).
2. Ввести бриф или загрузить контент-пакет, указать назначение и число слайдов.
3. Получить готовую колоду, превью каждого слайда, находки аудита и ссылки на
   скачивание `.pptx`, `.pdf` и `.html`.
4. Отметить находки, которые нужно исправить, и нажать «Исправить выбранные».

Шаблоны датасета в репозиторий не кладутся (это материалы организаторов,
каталог `output/` не хранится в git): после `git clone` список шаблонов пуст —
загрузите нужный через интерфейс.

### Девять колод сдачи (3 варианта вёрстки × 3 шаблона)

Готовые колоды во всех трёх форматах — в разделе
[Releases](https://github.com/Ivan239/lct2026/releases) репозитория. Воспроизвести:

```bash
# шаблоны датасета — под этими именами
cp "<шаблон VK Tech из датасета>.pptx"      output/templates/vk_tech.pptx
cp "<шаблон VK WorkSpace из датасета>.pptx" output/templates/vk_workspace.pptx
cp "<шаблон VK Education из датасета>.pptx" output/templates/vk_education.pptx

set -a; . ./.env; set +a
.venv/bin/python3 scripts/make_submission.py      # → output/submission/<шаблон>/<вариант>.{pptx,pdf,html}
```

### Проверить без интерфейса

```bash
# собрать деку офлайн на фикстурах, без обращения к модели
.venv/bin/python3 scripts/offline_probe.py --out /tmp/probe

# полный прогон с моделью и оценкой качества
set -a; . ./.env; set +a
.venv/bin/python3 scripts/improve_loop.py --model auto
```

## Тесты

```bash
.venv/bin/python3 -m pytest tests/ -q     # 435 тестов, без LLM и без LibreOffice
```

Тесты покрывают разбор шаблонов, спеку слотов, вёрстку, QA-проходы и
детерминированные критерии аудита. Каждое правило вёрстки закреплено тестом,
который падает на состоянии кода до этого правила.

## Структура репозитория

```
src/template_parser   разбор OOXML в структуру
src/design_system     кластеризация слайдов, архетипы, стиль-профиль шаблона
src/template_spec     спека: какие слайды и с какой ёмкостью можно заполнять
src/content_parser    планирование колоды и генерация текста блоков
src/matcher           подбор слайда шаблона под блок контента
src/generator         вёрстка: слоты, кегли, картинки, синтез недостающих ролей
src/qa                геометрические правки после вёрстки
src/evaluation        аудит: детерминированные критерии и render-based контраст
src/rendering         превью слайдов и экспорт .pdf/.html (LibreOffice + pdftoppm)
src/api               FastAPI
frontend              React + Vite
prompts               промпты агентов отдельными версионированными файлами
docs                  документация и журнал итераций
```
